각 패널의 **커맨드 라인**과 **명령 팔레트(Ctrl+K, Mac ⌘K)** 가 어떻게 움직이는지 정해요. 설계 단계 문서이고, 코드는 아직 없어요.

| 용어 | 뜻 |
|---|---|

| 칸 | 토큰이 들어갈 자리. 종목·시장·자산군·기능·인자 순서예요(§3.1) |
| 닫힌 칸 | 올 수 있는 값이 정해진 몇 개뿐인 칸(시장·자산군·기능). 종목 칸은 값이 수만 개라 닫힌 칸이 아니에요 |
| 함축 | 직접 치지 않았지만 앱이 정해서 채우는 값. 예: `005930`만 치면 시장 KS·자산군 EQUITY가 함축돼요 |
| 정확 / 앞부분 | 정확: 코드·이름이 글자 그대로 맞음. 앞부분: 친 글자가 앞쪽만 맞음(`0059` → 005930) |
| 흐린 글씨 | 커서 뒤에 회색으로 보이는 미리보기. 아직 입력된 글자가 아니고, Tab이나 →를 눌러야 들어가요 |
| 연한 토큰 | Tab을 눌렀을 때 앱이 대신 써 넣은 시장·자산군. 실제로 입력된 글자지만 직접 친 글자보다 연한 색이고, 종목을 바꾸면 따라 바뀌어요 |
| 강조(▸) | 목록에서 Tab을 누르면 채워질 줄 |
| 선택(▶) | 다음 Enter에 실행될 줄로 찍어 둔 상태. 아직 실행되지 않았어요 |
| 기억된 선택(↺) | 이 검색어로 지난번에 고른 줄을 기억해 목록 위로 올린 것. 선택(▶)과 달리 Enter가 바로 실행하지 않아요 |
| 진행 표시 | 입력줄 아래에서 `종목 ✓ │ 시장 ✓ │ 자산군 ✓ │ 기능 ▸`처럼 어디까지 채웠는지 보여 주는 줄(§4.7) |
| 순위 등급(T0~T9) | 후보 줄이 얼마나 잘 맞았는지에 따른 등급. 숫자가 작을수록 목록 위에 와요(§6.4) |
| 띄운 종목 | 그 패널에 지금 보이고 있는 종목 |
| 인자 | 기능 뒤에 붙이는 추가 값. 예: COMP에 비교할 종목들 |
| 마스터 | 증권사가 내려 주는 전체 종목 목록 파일 |
| 색인 | 그 목록을 빨리 찾으려고 앱이 메모리에 만들어 두는 찾아보기 표 |
| IME(입력기) | 키보드로 친 자판을 한글 글자로 바꿔 주는 Windows·Mac 기능 |
| 조합 중 | `ㅎ` → `헤` → `헬`처럼 한 글자를 아직 만들고 있는 상태 |

## 1. 개요

### 1.1 무엇을 만드나

- 패널마다 커맨드 라인이 하나씩 있어요. 명령 팔레트도 같은 엔진(해석기와 완성기)을 써요.
- 사용자 요청: "초보자가 티커를 치면 다음에 무엇을 칠지 자동완성으로 보여 주고, Tab으로 채우게. VS Code IntelliSense처럼." 그래서 입력하는 동안 **흐린 글씨**(다음에 올 내용)와 **후보 목록**을 보여 주고, **Tab**으로 채워요.
- 전문가는 `005930 KS EQUITY GP`를 끝까지 치고 Enter를 누르면 돼요. 도움 기능이 끼어들지 않아요.
- AI·LLM 기능은 없어요. 찾기와 순서는 모두 정해진 규칙을 따라요.
- Electron 데스크톱 앱이에요(Windows 우선, macOS Apple Silicon 다음). 키는 두 운영체제를 함께 적어요.

### 1.2 일곱 가지 원칙

1. **Tab은 채우고, Enter는 실행해요.** Tab은 아무것도 실행하지 않아요. Enter는 블룸버그의 `<GO>`예요.
2. **애매하면 Enter를 두 번.** 입력이 여러 뜻일 수 있으면 첫 Enter는 1번 줄을 **선택**만 하고, 두 번째 Enter가 실행해요. 보지 않은 것을 실행하지 않으려는 거예요.
3. **⏎ 라벨이 Enter가 할 일을 늘 알려 줘요.** 커맨드 라인 오른쪽 끝에, 모든 도움 수준에서 보여요. 흐린 글씨, ⏎ 라벨, 실제 실행은 모두 같은 해석 결과를 읽어요. 그래서 미리 보기와 결과가 다를 수 없어요.
4. **입력한 것이 이겨요.** 이미 뜻이 정해진 토큰은 바꾸지 않아요. 끝까지 쳐서 Enter를 누르면 어느 도움 수준에서나 결과가 같아요. 도움 수준은 "보이는 것"만 바꾸고, 키가 하는 일은 바꾸지 않아요.
5. **목록은 기다리지 않아요.** 메모리에 올린 색인에서 바로 찾고, 후보 목록을 그리려고 네트워크를 기다리지 않아요.
6. **한글을 치는 도중(조합 중)에는 앱이 입력칸 글자를 고치지 않아요.** 친 글자는 그대로 보여요. 그사이 누른 Tab·Enter는 기억해 두었다가 글자가 완성된 뒤 처리해요(§8).
7. **늘 표준형으로 다시 보여 줘요.** `삼성`, `헤`, `차트`, `gp 005930` 무엇을 쳐도 패널과 기록에는 `005930 KS <EQUITY> GP`가 남아요. 보면서 문법을 익히게 돼요. (`<EQUITY>`는 노란 칩으로 그린 자산군 단어를 글로 적은 표기예요.)

**같은 결과에 대한 약속:** 같은 입력 + 화면에 보이는 상태 → 같은 결과. "보이는 상태"는 패널에 띄운 종목과 기능, 연동 그룹 표시, ↺(기억된 선택) 표시, ⏎ 라벨이에요. 사용 기록은 목록 순서만 바꿔요. Enter 한 번의 결과가 바뀌는 경우는 하나뿐이에요: 겹치는 이름에서 1번이 아닌 같은 줄을 두 번 고르거나 `기본값으로`를 눌러 "내 기본값"을 정했을 때(§7.4). 이때는 알림이 뜨고 ⏎ 라벨에 `(내가 정한 기본값 ↺)`가 붙어요.

## 2. 기본 키

"Mod"는 Windows의 Ctrl, Mac의 ⌘예요. 단축키(Tab·Enter·화살표·Mod+Shift+E 같은 것)는 그 키가 만든 글자가 아니라 **키보드에서 눌린 자리**로 알아봐요. 한글 모드에서는 같은 자리를 눌러도 `G` 대신 `ㅎ`이 나오기 때문이에요.

| Windows | Mac | 하는 일 |
|---|---|---|
| **Tab** | Tab | 강조된 줄(▸)로 지금 토큰을 채우고, 정해지는 칸(시장·자산군)을 연하게 써 넣고, 다음 칸이 있으면 공백을 넣어요. 다음 칸이 고르기라면 그 목록을 열어요. **실행은 안 해요.** 줄이 완성됐으면 아무 일도 없고, 라벨이 `⏎로 실행`으로 잠깐 깜빡여요. |
| **Enter**, 숫자패드 Enter | Return, 숫자패드 Enter | 실행. 애매하면 1번 줄을 선택만 해요(§3.6). 꾹 눌러 반복되는 Enter는 무시해요. |
| **↓ / ↑** | ↓ / ↑ | 목록에서 강조를 옮기고 그 줄을 **선택**(▶)해요. 흐린 글씨도 따라가요. 끝에서 멈춰요. |
| **→ / End** | → / ⌘→ | 커서가 줄 끝이고 흐린 글씨가 있으면 흐린 글씨를 전부 받아들여요. 아니면 보통 커서 이동. |
| Ctrl+→ | Option+→ | 흐린 글씨에서 다음 토큰 하나만 받아들여요. |
| **Esc** | Esc | 1번째: 도움말 카드·목록·흐린 글씨를 닫아요. 2번째: 줄을 지워요(Mod+Z로 복구). 빈 줄에서: 패널 본문으로 포커스를 옮겨요(§10.1). |
| **Space** | Space | 보통 글자예요. 제안을 받아들이지 않아요. 그래서 `AAP␠`가 AAPL로 바뀌지 않아요. |
| **Shift+Tab** | Shift+Tab | 직접 고른 이전 토큰을 다시 열어 고쳐요(연하게 써 넣은 시장·자산군은 건너뜀). 빈 줄이고 목록이 없으면 보통 포커스 이동. |
| **F1** 또는 Ctrl+/ | ⌘/ | 강조된 줄의 설명 창. 한 번 더 누르면 문법 요약. |
| 마우스 클릭 | 같음 | 줄 클릭 = Tab. 더블클릭 = Tab 다음 Enter. 클릭 한 번으로는 실행되지 않아요. |

나머지 키, Windows·Mac 차이, Electron 키 충돌은 §10에 있어요.

## 3. 명령 문법

### 3.1 칸 구성

표준 순서는 `종목 시장 자산군 기능 인자 ⏎`예요.

| 칸 | 꼭 필요한가 | 받는 형태 | 비워 두면 |
|---|---|---|---|
| **종목** | 종목이 필요한 기능일 때만 | KRX 코드(`005930`), 미국 티커(`AAPL`, `BRK.B`), 코인(`BTC`, `BTCUSDT`, `BTC/USDT`), 환율(`USDKRW`, `USD/KRW`), 지수(`KOSPI`, `코스피`), 한글·영문 이름, 초성, 별칭 | 패널에 띄운 종목. 없으면 `[종목]` 자리 표시 |
| **시장** | 아니요 | `KS`(코스피), `KQ`(코스닥), `US`. `UN`·`UW`·`UQ`·`UA`·`UP`·`NAS`·`NYS`·`AMS`는 상장을 확인해 `US`로 바꿔요. `BN`·`BINANCE`는 입력해도 되지만 무시해요. 기본값(블룸버그 관례와 같은지 확인 필요) | 상장 정보에서. 코인·환율·지수에는 시장 칸이 없어요 |
| **자산군**(노란 키) | 같은 글자가 두 자산군에 있을 때만 | `EQUITY`·`EQ`·`EQY`·`주식`, `CRYPTO`·`CRY`, `CURNCY`·`CRNCY`·`CUR`·`FX`, `INDEX`·`IDX`·`IND`, 단축키 Mod+Shift+E/C/X/I | 종목의 자산군에서 |
| **기능** | 종목이 없을 때 필요. 종목 뒤에선 생략 가능 | 코드(`GP`), 한국어 키워드(`차트`), 키워드 초성(`ㅊㅌ`), 한글 모드로 친 코드(`헤`) | §3.4 |
| **인자** | v0.2부터 | 기능마다 달라요(COMP는 종목들, MOST는 시장, HMAP은 지수) | 기능마다 달라요 |
| **⏎** | — | Enter. 기능 바로 뒤, 줄 끝의 `GO`·`<GO>`는 지워요(§7.5) | — |

- `지수`, `코인`, `환율`은 자산군 단어로 쓰지 않아요. 각각 WEI, CRYP, FXC의 키워드예요(§12.3).
- 시장·자산군 단어 중에도 미국 티커가 있어요(`UA`, `UN`, `AMS`, `BN`, `IND`). 종목 뒤에서는 시장·자산군 단어로, 줄 첫머리에서는 종목으로 읽어요(§3.3).
- 입력칸에는 꺾쇠 없이 `005930 KS EQUITY GP`처럼 들어가요. 붙여넣은 `<`, `>`는 읽을 때 지워요.

### 3.2 줄여 쓰기

| 입력 | 실행 결과 | 규칙 |
|---|---|---|
| `005930 GP`, `005930 gp` | 같음 | 시장·자산군은 종목에서 정해져요 |
| `GP 005930`, `삼성전자 GP`, `차트 삼성전자` | 같음 | 기능 먼저, 이름도 받아요. 표준 순서로 다시 써요 |
| `005930` | `005930 KS <EQUITY> <기본 기능>` | 종목만(§3.4) |
| `GIP` | `<띄운 종목> GIP` | 기능만 |
| `MON`, `WEI`, `FXC`, `CRYP` | 그대로 | 종목이 필요 없는 기능. 패널은 띄운 종목을 기억해요 |
| `BTC`, `btcusdt`, `BTC/USDT`, `비트코인` | `BTC <CRYPTO>` (= BTC/USDT) | USDT 쌍만 |
| `USDKRW`, `USD/KRW`, `원달러` | `USDKRW <CURNCY>` | 환율. `KOSPI`·`코스피`도 같은 식으로 지수 |
| `KRW`, `EUR`, `JPY` (통화 코드 하나) | 그 통화의 원화 환율(`EUR` → EURKRW, `JPY` → JPYKRW). `KRW`만 치면 `USDKRW` | 기본값(바꿀 수 있음). 블룸버그 단일 통화 관례와 같은지는 확인 필요 |
| `CRYPTO⏎` / `CURNCY⏎` / `INDEX⏎` | CRYP / FXC / WEI | 자산군의 대표 기능. `EQUITY⏎`는 v0.1에서는 주식 종목만 보이는 후보 목록을 열고, v0.2부터는 MOST(상위 종목)를 열어요 |
| `?`, `도움말` / `설정`, `PDF` | 도움말 / 설정 창 | `PDF`는 블룸버그의 개인 설정 명령. `HELP⏎`는 미정(§7.5) |
| 붙여넣은 `IBM US Equity GP <GO>` | 읽기만 해요. 꺾쇠와 끝의 GO를 지워요 | 붙여넣기는 절대 실행하지 않아요 |

### 3.3 위치에 따라 달라지는 예약어

| 위치 | 읽는 순서 |
|---|---|
| 줄 첫머리 | ① 기능 코드(뒤에 시장·자산군이 오지 않을 때) ② 한국어 키워드·별칭 ③ 종목 ④ 자산군 단어 하나만(그 자산군으로 거르기). 시장 단어는 예약하지 않아요(`US`로 시작하는 이름이 있어요). 영문·숫자 2글자 이하는 무엇이든 "정확"으로 치지 않아요(§6.3) |
| 종목 뒤 | 시장 → 자산군 → 기능. 종목이 필요 없는 기능도 돼요(`005930 WEI`) |
| 시장 뒤 | 자산군 → 기능 |
| 자산군 뒤 | 기능 |
| 기능 뒤 | 인자. 또는 기능이 종목을 받고 앞에 종목이 없었다면 종목 |

- "첫 단어가 기능 코드면 기능으로 읽는다"는 블룸버그 동작을 추정한 **기본값**이에요(확인 필요). 같은 글자의 종목을 원하면 `FXC US`처럼 시장을 붙이거나 2번 줄을 골라요.
- **앞부분(접두)은 그 자리에서 유효한 모든 것과 함께 비교해요.** 시장·자산군·기능을 함께 보고, 아직 만들지 않은 기능(IMAP, ECO 등)도 넣어요. 예: 종목 뒤 `CR`는 CRYPTO·CRNCY와 CRYP 기능이 모두 후보예요. 앞부분은 후보가 하나여도 Enter 한 번에 실행되지 않아요(§3.5). 안 만든 기능까지 넣는 이유는 버전이 올라가도 같은 입력의 후보가 바뀌지 않게 하려는 거예요.
- 정확한 단어가 앞부분보다 먼저예요. `BTC CRYP`의 CRYP는 CRYPTO의 앞부분이기도 하지만 CRYP 기능과 정확히 같아서 기능으로 읽어요. ⏎ 라벨이 `코인 시세판 (CRYP)`이라고 보여 줘요.

### 3.4 기본값과 함축 값

- **상장이 하나뿐인 종목**은 시장과 자산군이 저절로 정해져요.
- **종목만 입력하고 Enter**: 미정 — 07-open-questions.md 참고.
  - 제안: **지금 기능 유지** — 지금 기능이 종목용이고 이 종목에 쓸 수 있을 때. 아니면 GP(지금은 모든 자산군의 기본 기능이 GP예요).
  - 예: GIP를 보던 패널에서 `005930⏎` → `005930 KS EQUITY GIP`. WEI를 보던 패널에서는 WEI가 종목용이 아니라서 → `005930 KS EQUITY GP`.
  - 블룸버그식 "그 종목의 기능 메뉴 열기"는 v0.2에 설정 선택지로 추가돼요. v0.1의 설정에는 "지금 기능 유지" 하나만 있어요.
- **종목이 필요한 기능을 종목 없이** 치면 패널에 띄운 종목을 써요. 없으면 "종목 필요" 상태예요.
- **연동 패널**에서는 띄운 종목이 곧 그룹 종목이에요(그룹 안의 모든 패널이 같은 종목을 써요). 직접 입력한 종목은 그룹 전체에 퍼져요. `005930 WEI`도 마찬가지예요. 기능 변경은 퍼지지 않아요.
- **종목이 필요 없는 기능**은 그대로 실행되고, 패널은 띄운 종목을 기억해요. `WEI⏎` 다음 `GP⏎⏎`(GP는 두 글자라 고른 뒤 실행, §6.3)로 이전 차트가 돌아와요.
- **쓸 수 있는 기능은 계산해요.** 기능이 지원하는 자산군 + 데이터 제공처가 필요한 데이터를 주는지로 정해요. 예: 무료 환율 소스에 분봉이 없으면 USDKRW에서 GIP가 저절로 빠져요(분봉 제공 여부 확인 필요).

### 3.5 토큰 상태와 Enter

Enter 한 번에 실행되는 토큰은 **정확, 함축, 교정, 닫힌 칸의 한/영 변환** 네 가지와, 사용자가 이미 **고른** 토큰뿐이에요. 나머지는 첫 Enter에 선택만 해요. 앞부분 일치는 후보가 하나뿐이어도 선택만 해요. 마스터 파일에 종목이 하나 늘면 같은 입력의 결과가 달라지기 때문이에요.

| 상태 | 예 | 첫 Enter |
|---|---|---|
| 정확 | `005930`, `AAPL`, `삼성전자`, `차트`, `WEI`, 종목 뒤 `GP` | 실행 |
| 함축 | 종목에서 정해진 시장·자산군, 기본 기능, 띄운 종목 | 실행 |
| 교정 | `005930 KQ` → KS (KQ에 005930이 없을 때만) | 실행. 주황 점선 밑줄 |
| 닫힌 칸 한/영 변환 | 종목 뒤 `헤` → GP | 실행. 주황 점선 밑줄 |
| 고른 토큰 | Tab·클릭·선택(▶)으로 받아들인 토큰. 글자를 고치기 전까지 | 실행 |
| 앞부분(후보 하나여도) | `0059`, `삼성`, `삼성바이` | 선택만 |
| 짧은 입력 | 한 글자 전부(`G`, `ㅅ`), 첫 칸 영문·숫자 2글자 이하(`GP`, `FA`, `GS`) | 선택만 |
| 초성·자모·부분·오타 | `ㅅㅅㅈㅈ`, `5930`, `apel` | 선택만 |
| 첫 칸의 한/영 변환 | `ㅁ메ㅣ` → AAPL | 선택만 |
| 겹침 | `CVX`(셰브론 / Convex 코인), 기본값이 없을 때 | 선택만. 두 줄 모두 보여 줘요(§7) |
| 잘못됨 | `BTC CRYPTO FA`, `VOD LN`, v0.1에서 `DES` | 실행 안 함. 빨간 밑줄 + ✗, 고침이 1번 줄 |

모든 토큰이 실행 가능 상태이고, 필요한 종목이 있고, 기능이 만들어져 있고 그 자산군에 맞으면 **실행 준비** 상태예요.

### 3.6 Enter 처리 순서

위에서부터 처음 맞는 것 하나만 해요.

1. **반복 입력**(꾹 누름)이면 무시해요.
2. **한글 조합 중**이면 의도만 기록하고, 음절이 끝난 뒤 한 번만 처리해요(§8).
3. **선택된 줄(▶)이 있으면** Tab처럼 받아들여요. 실행 준비가 되면 실행하고, 아니면 다음 칸에서 멈춰요.
4. **실행 준비 상태면** 지금 패널에서 실행해요. 줄을 비우고, 표준형을 보여 주고, 기록에 넣어요.
5. **문제가 있는 토큰**을 왼쪽부터 보고 처음 걸리는 것 하나를 처리해요.
   - 고르기가 필요하면: 그 토큰 목록의 1번 줄을 선택(▶)해요. 목록이 닫혀 있으면 열어요. 라벨이 `⏎ 실행: …`으로 바뀌어요. 아무것도 실행하지 않아요.
   - 종목이 필요한데 없으면: `[종목]` 자리 표시와 최근 종목 목록을 보여 줘요.
   - 잘못됐으면: 진행 표시와 라벨에 빨간 메시지(✗)를 보이고, 고침을 1번 줄에 고정해요(Tab으로 적용).
6. **일치하는 것이 없으면** `'XYZQ'와 일치하는 종목·기능이 없어요` 줄을 보여 줘요. v0.2부터는 두 번째 Enter로 로컬 검색 페이지를 열어요.
7. **빈 줄이면** 아무 일도 없어요. 입문에서는 시작 목록을 열어요.

### 4.2 입력줄

- 글꼴: 한글이 정확히 영문 2칸 폭인 고정폭 글꼴(D2Coding 등. 구현할 때 확정, [02](02-ui.md) 참고).
- 대문자는 화면에만 대문자로 보이게 하고, 입력값 자체는 바꾸지 않아요.
- 자산군 단어는 노란 칩(`#F5C542` 바탕, 검정 글자) 위에 여백 없이 그려서 글자 줄이 어긋나지 않게 해요.
- 일반 입력칸 하나로는 칩·흐린 글씨·밑줄을 그릴 수 없어요. 구현 방식은 §9에서 두 안을 시험해 골라요.
- **문맥 칩**: 입력값 밖 왼쪽에 흐리게. 기능만 친 줄에서 함축된 종목을 알려 줘요. 연동 패널이면 그룹 색 점(`● 연동 AAPL US`).
- 오른쪽 끝에 마우스용 **`?` 버튼**, 한글 조합이 있었음을 알리는 주황 **`[한]` 배지**(§8.1 K10).
- 색은 [02](02-ui.md)를 따라요. 주황 `#FB8B1E`은 일치 글자·지금 칸·FN 배지·선택 줄 막대·포커스 테두리에 써요. 오류는 빨간 밑줄 + ✗예요. 빨강은 등락 색으로도 쓰여서 색만으로 알리지 않아요.

### 4.3 흐린 글씨

커서 뒤에 흐리게 보이는 다음 내용이에요.

- **두 부분으로 나눠 그려요.** Tab이 넣을 부분은 더 밝게, 그 뒤 나머지(→ 또는 Enter가 쓰는 부분, 주로 기능)는 경계 표시 `¦` 뒤에 `#7A7A7A`로 그려요. 어떤 흐린 글씨도 `#7A7A7A`보다 어둡지 않아요. 밝은 쪽의 정확한 값은 목업에서 정해요(기본값).
- **두 종류가 있어요.** **확정**은 지금 Enter를 누르면 이 내용대로 실행돼요. **후보**는 Tab이나 →로만 들어가고 Enter는 선택만 해요. 후보는 점선 상자와 끝의 `?` 표시로 구분해요. 회색 밝기 차이만으로 구분하지 않아요.
- 한글 조합 중에는 숨겨요. 받침이 다음 글자로 옮겨 가면서(예: `간` 다음에 `ㅏ`를 치면 `가나`가 되는 현상, '도깨비불'이라고 해요) 흐린 글씨가 튀기 때문이에요.
- 기능을 흐린 글씨에 넣는 것은 기본값(바꿀 수 있음)이에요. 기능을 추측해 넣으면 헷갈릴 수 있어서, Enter가 실제로 쓸 기능일 때만 경계 뒤에 넣어요. 써 보고 헷갈리면 `[기능]` 자리 표시로 바꿔요.

### 4.4 ⏎ 라벨

| 라벨 | 뜻 |
|---|---|
| `⏎ 실행: 삼성전자 가격 차트` | Enter가 이것을 실행해요 |
| `⏎ 선택: 005930 삼성전자` | Enter는 1번 줄을 고르기만 해요 |
| `⏎ 실행: … (헤 → GP)`, `(KQ → KS)` | 고쳐서 실행해요 |
| `⏎ 실행: … (내가 정한 기본값 ↺)` | 겹침에서 사용자가 정한 뜻으로 실행해요 |
| `⏎ 종목 필요: GP에 쓸 종목을 입력하세요` | 실행하지 않아요 |
| `⏎ 실행 안 됨: FA는 주식 전용` | 오류예요 |
| `⏎ 일치 없음` (v0.2부터 `⏎ 검색`) | 찾은 것이 없어요 |

좁은 패널에서는 `⏎ GP · 삼성전자`처럼 줄여요.

### 4.5 후보 목록

- 패널이 있는 그 창 안에 그려요. 떼어낸 창이면 그 창의 문서 안에 그려요. 최소 폭 360px, 지금 토큰 위치에 붙고, 화면 아래쪽이면 위로 열려요.
- 최대 8줄 + `더 보기 (+N)`(자산군별로 묶은 최대 200줄). 좁으면 열을 영문 이름 → 설명 → 표준형 순으로 빼요.
- 강조된 줄(▸, Tab 대상)은 배경 `#16325E`. 선택된 줄(▶, Enter 대상)은 같은 배경 + 주황 왼쪽 막대 + 오른쪽 `⏎`. 일치한 글자는 주황(굵게 하지 않아 폭이 안 바뀜).

```
▸ EQ·KS  005930  [삼성]전자   Samsung Elec.   코스피 · 보통주   ↺   005930 KS EQUITY
  배지    코드     한글 이름    영문(넓을 때)    시장·종류·표시    기억  이 줄이 만드는 표준형
▸ FN     GP      가격 차트    일·주·월봉 캔들                         005930 GP
```

- 기능 줄 오른쪽 열은 지금 종목에 대한 **가장 짧은 명령**이에요. 줄여 쓰기를 가르쳐요. 입문에서는 지금 기능에 `● 현재` 표시.
- 배지: `EQ·KS`, `EQ·KQ`, `EQ·US`, `CRY`, `CUR`, `IDX`(노랑), `FN`(주황), `HIST`(최근 기록에서 온 줄), `ALIAS`(v0.2, 사용자가 만든 별칭)(회색). 표시(회색 테두리): `PREF`, `ETF`, `ETN`, `SPAC`, `ADR`, `HALT`, `DELISTED`(흐리게), `한/영`, `영→한`.
- 특수 줄:
  - 변환: `헤 → GP`, `ㅁ메ㅣ → AAPL`, `tkatjd → 삼성전자 (영→한)`.
  - 고침: `005930은 코스피예요 → KS` (1번 고정, Tab으로 적용).
  - 사용 불가: 아직 안 만든 기능을 정확히 쳤을 때 `DES 종목 개요 — v0.2에서 제공 예정`. 입문에서는 자산군에 안 맞는 기능도 `── 이 종목에는 쓸 수 없음 ──` 아래에 이유와 함께.
  - 일치 없음: `'XYZQ'와 일치하는 종목·기능이 없어요`. 목록이 말없이 닫히지 않아요.
  - 마스터에 없음: `목록에 없는 코드예요 — ⏎로 KIS에서 직접 조회` (선택한 뒤 두 번째 Enter에 조회).

### 4.6 설명 창

- 목록 오른쪽, 창에 280px 이상 남을 때 보여요. 입문은 자동, 다른 수준은 F1·Mod+/. 한 번 더 누르면 문법 요약으로 바뀌어요.
- 종목: 한글·영문 이름, 코드, 시장, 종류, 업종, 상장 상태, 헷갈리기 쉬운 종목(`005935 삼성전자우 (우선주)`), 쓸 수 있는 기능. ADR이면 KRX 종목과 서로 연결해요.
- 기능: 이름, 보여 주는 것, 종목 필요 여부, 지원 자산군, 예시 2–3개, 비슷한 기능.
- 변환·고침·오류: 한/영이 무엇인지, 왜 안 되는지, Tab이 무엇을 하는지.
- v0.2 간단 시세: 목록은 시세를 기다리지 않아요. 150ms 뒤 요청, 취소 가능, 받은 값은 10초 동안 다시 써요(기본값). 화살표로 줄을 훑어도 KIS 요청은 한 번에 하나만 보내고, 받아 둔 값은 패널의 시세와 함께 써요.

### 4.7 진행 표시

입력줄 아래에서 어디까지 채웠는지 보여 주는 한 줄이에요. ✓ 채운 칸(흰색), ▸ 지금 칸(주황), · 빈 칸(회색), ✗ 오류(빨강 + ✗). 칸을 클릭하면 커서가 그 칸으로 가요. 문구 예: `종목을 고르세요 — Tab 또는 ↓`, `다음: 기능을 고르세요 — Tab = GP 가격 차트, ↓ 다른 기능`, `⏎ GO`, `BTC → 코인(BTC/USDT)`, `KQ → KS`, `ㅅㅅㅈㅈ → 005930 삼성전자`. 오류는 창을 띄우지 않고 줄을 지우지 않아요. 고침은 늘 1번 줄에 있어요.

### 4.8 빈 줄 문구

입력값이 아니라 빈 입력칸에 흐리게 보이는 안내 문구로 하나만 보여요. 우선순위:

1. 패널에 띄운 명령이 있으면 그 명령을 흐리게(`005930 KS EQUITY GP`). 첫 키가 덮어써요.
2. 패널이 비었고 입문이면 `명령 입력 — 종목코드·회사명·기능 (예: 005930, 삼성, AAPL, BTC, 차트)`.
3. 그 밖에는 `명령 입력 · 도움말 ?`. 빈 패널 본문의 안내(`명령을 입력하세요 · 예: 005930 GP ⏎`)는 본문에 따로 보여요.

## 5. 걸어 보기 예시

표시: `▌` 커서, `‹…›` 확정 흐린 글씨(지금 Enter를 누르면 이 내용대로 실행), `«…»` 후보 흐린 글씨(Enter는 선택만, 화면에선 점선 상자 + `?`), `¦` 경계(왼쪽은 Tab이 넣을 부분), `[ab]` 일치한 글자(주황), `▸` 강조된 줄(Tab 대상), `▶` 선택된 줄(Enter 대상). 한글은 2칸 폭이라 열 맞춤은 대략이에요. 종목 줄의 순서와 이름은 예시이고, 실제 순서는 마스터 파일과 인기도로 정해져요.

### (a) `0059` → Tab → `G` → Tab → Enter

시작: 빈 새 패널, 입문, 영문 모드.

```
> 0059▌«30 KS EQUITY¦ GP»                               ⏎ 선택: 005930 삼성전자
 ▸EQ·KS  [0059]30  삼성전자        코스피 · 보통주        005930 KS EQUITY
  EQ·KS  [0059]35  └ 삼성전자우    코스피 · 우선주 PREF   005935 KS EQUITY
  EQ·KS  [0059]40  NH투자증권      코스피 · 보통주        005940 KS EQUITY
  …      더 보기 (+N)
 종목 ▸ 0059… │ 시장 · │ 자산군 · │ 기능 ·
 Tab 자동완성 · ↑↓ 고르기 · ⏎ 실행 · Esc 닫기 · F1 설명
```
- 모두 코드 앞부분 일치라 흐린 글씨는 후보예요. 우선주는 보통주 바로 아래예요. 설명 창에는 `헷갈리기 쉬운 종목: 005935 삼성전자우 (우선주)`가 보여요.
- 지금 누르면: Tab → `005930 KS EQUITY ▌`. →를 누르면 흐린 글씨 전부. Enter → 1번 줄 선택, 라벨이 `⏎ 실행: 005930 KS EQUITY GP · 삼성전자 가격 차트`로. `30`을 더 치면 정확해져서 흐린 글씨가 확정으로 바뀌어요.

**Tab 후**
```
> 005930 KS EQUITY ▌‹GP›                                ⏎ 실행: 삼성전자 가격 차트
 ▸FN  GP   가격 차트   일·주·월봉 캔들          005930 GP
  FN  GIP  장중 차트   오늘 장중 움직임(분봉)   005930 GIP
 종목 ✓ 005930 삼성전자 │ 시장 ✓ KS 코스피 │ 자산군 ✓ EQUITY 주식 │ 기능 ▸ Tab = GP
```
- `KS EQUITY`는 연하게 써 넣은 토큰이에요. 종목을 바꾸면 따라 바뀌어요.
- 빈 패널이라 GP(자산군 기본)가 함축돼요. 여기서 Enter를 누르면 바로 GP가 실행돼요.
- v0.1은 만든 기능만 보여요. v0.2부터 DES, N, COMP가, v0.3부터 FA가 더해져요.

**`G` 입력 후** → `005930 KS EQUITY G▌«P»`, 라벨 `⏎ 선택: GP 가격 차트`, 목록은 GP·GIP. 한 글자라 정확이 아니어서 Enter는 GP를 선택만 해요.

**Tab 후** → `005930 KS EQUITY GP▌`, 라벨 `⏎ 실행: 삼성전자 가격 차트`, 진행 표시 끝에 `⏎ GO`. 뒤에 칸이 없으니 공백을 넣지 않고 목록을 닫아요.

**Enter 후** → 실행. 패널 커맨드 라인에 `005930 KS EQUITY GP`가 흐리게 남고, 입문이면 팁 `다음엔 005930 GP ⏎ 만 입력해도 돼요 (KS·EQUITY는 자동)`이 보여요.

키 8번이에요. 같은 결과의 짧은 길: `0059⏎⏎`(6번, 첫 Enter 선택·두 번째 실행), `0059→⏎`(6번), `005930⏎`(7번), `005930 gp⏎`(10번).

### (b) `삼성` (한글 이름) 다음 고르기

시작: 빈 패널, 한글 모드(두벌식 키 t k a t j d).

- `ㅅ` 한 글자일 때: 삼성전자, └삼성전자우, 삼성바이오로직스, 셀트리온… 처럼 ㅅ으로 시작하는 이름이 보여요. 한 글자라 모두 고르기예요. `ㅅ`의 한/영 변환(T)은 한 글자라 보이지 않고, 키워드 `설정`도 자모 하나로는 올라오지 않아요(§6.4).
- 조합 중에도 입력할 때마다 목록이 바뀌어요. 흐린 글씨는 숨겨요.

```
> 삼성▌ (조합 중)                               [한]   ⏎ 선택: 005930 삼성전자
 ▸EQ·KS  005930  [삼성]전자            코스피 · 보통주        005930 KS EQUITY
  EQ·KS  005935  └ [삼성]전자우        코스피 · 우선주 PREF   005935 KS EQUITY
  EQ·KS  207940  [삼성]바이오로직스    코스피                 207940 KS EQUITY
  EQ·KS  006400  [삼성]SDI             코스피                 006400 KS EQUITY
  …      더 보기 (+N, ETF·ETN 포함)
```

**`성`이 아직 조합 중일 때 Tab.** 쉽게 말해, `성`을 아직 치는 중에 Tab을 눌러도 앱은 그 Tab을 기억해 두었다가 글자가 완성된 뒤 한 번만 처리해요. 아래는 개발용 이벤트 순서예요(Mac Chrome에서 보고된 순서, Windows는 확인 필요).
```
keydown Tab (조합 중)   → 기본 동작 막음. 의도 #7 = 받아들이기(줄 id: 005930) 기록
compositionend "삼성"
input                   → 목록 다시 계산. 이 input 뒤에야 입력칸에 씀
keydown Tab (진짜)      → 의도 #7을 한 번 실행 → 채우기
(진짜 keydown이 대체 시간 안에 안 오면 그때 #7 실행, 늦게 온 Tab은 삼킴 — §8.1 K3)
```
- 결과는 `005930 KS EQUITY ▌‹GP›`, 진행 표시 `종목 ✓ 삼성 → 005930 삼성전자`. Mod+Z 한 번이면 `삼성`으로 돌아가요. Backspace는 보통처럼 한 글자만 지워요.

**화살표로 다른 줄 고르기** (`삼성` 상태에서 ↓ ↓)
```
> 삼성▌                                         [한]   ⏎ 실행: 삼성바이오로직스 가격 차트 (GP)
 ▶EQ·KS  207940  [삼성]바이오로직스    코스피     207940 KS EQUITY      ⏎
```
- 첫 ↓가 조합 중에 오면 "옮겨 갈 줄의 id"로 기록했다가 음절이 끝난 뒤 그 id에 적용해요. 몇 번째 줄인지가 아니라 어느 줄인지로 기억해요.
- 화살표로 옮긴 줄은 선택돼요. Enter → 받아들이고 실행(종목만 → 기본 기능, 빈 패널이라 GP). Tab이면 채우기만 해요. 클릭은 Tab과 같아요.
- 다른 길: `삼성전자 gp⏎`, `삼성전자 헤⏎`(닫힌 칸 변환), `삼성⏎⏎`.

### (c) `ㅅㅅㅈㅈ` (초성 검색)

```
> ㅅㅅㅈㅈ▌                                     [한]   ⏎ 선택: 005930 삼성전자
 ▸EQ·KS  005930  [삼성전자]            코스피 · 보통주        005930 KS EQUITY
  EQ·KS  005935  └ [삼성전자]우        코스피 · 우선주 PREF   005935 KS EQUITY
```
- 초성이 맞은 음절을 주황으로 칠해요. 초성 전체 일치(삼성전자)가 초성 앞부분 일치(삼성전자우)보다 위예요.
- Tab → `005930 KS EQUITY ▌‹GP›`. 진행 표시에 `ㅅㅅㅈㅈ → 005930 삼성전자`가 보여 코드를 익혀요.
- Enter → 선택만(초성은 늘 고르기). 두 번째 Enter에 실행.
- IME가 자음 둘을 겹자음으로 합치면(ㄱ+ㅅ→ㄳ 등) 나눠서 찾아요.

### (d) 한글 모드로 `GP`를 쳐서 `헤`가 된 경우

**주 경우: 종목 바로 뒤.** (b)의 Tab 다음, 아직 한글 모드예요. g를 누르면 `ㅎ`:
```
> 005930 KS EQUITY ㅎ▌ (조합 중)                [한]   ⏎ 선택: GP 가격 차트
 ▸FN  ㅎ→[G]P             가격 차트       한/영                  005930 GP
  FN  ㅎ→[G]IP            장중 차트       한/영                  005930 GIP
  FN  [ㅎ]→환율 FXC        환율 매트릭스   키워드 · 종목 불필요    FXC
```
- 기능 칸의 한글은 키워드·초성·한/영 변환을 함께 찾아요. 모두 앞부분이라 선택만, 순서는 기능 칸 순서(§6.7)예요.

p를 누르면 `헤`:
```
> 005930 KS EQUITY 헤▌ (조합 중)                [한]   ⏎ 실행: 삼성전자 가격 차트 (헤 → GP)
 ▸FN  헤 → GP   가격 차트   한/영: 영문 코드로 바꿔 넣어요        005930 GP
 기능 ✓ GP (헤 → GP) │ 한글 입력 중이에요 — 기능 코드는 영문이에요 (한/영 키)
```
- 닫힌 칸의 정확한 변환이라 실행 가능해요. `헤`에 주황 점선 밑줄.
- **조합 중 Enter**: ① 의도 기록 ② compositionend ③ 그다음 input 이벤트 뒤에 `헤`→`GP` 고쳐 쓰기(Ctrl+Z 한 번으로 되돌릴 수 있게) ④ 진짜 Enter에서 한 번 실행. 한국어 사용자가 기대하는 대로 Enter 한 번이면 돼요.
- **Tab**: `GP`로 고쳐 쓰고 목록을 닫아요. 바로 다음 Backspace는 `헤`로 되돌려요.
- **Space**: 고쳐 쓰지 않아요. `헤`로 남지만(밑줄) 여전히 GP로 실행돼요.
- 기록에는 늘 `005930 KS <EQUITY> GP`가 남아요. 한/영 팁은 최대 3번.

**변형: 첫 단어로 친 경우** (AAPL을 띄운 패널, 빈 줄):
```
> [AAPL US ›] 헤▌ (조합 중)                     [한]   ⏎ 선택: 헬릭스미스
 ▸EQ·KQ  084990  [헤]→헬릭스미스        코스닥 (자모 일치: 헤가 헬이 될 수 있음)
  FN     헤 → GP  가격 차트 · AAPL US (띄운 종목)   한/영
```
- 첫 칸의 한글은 이름 검색이 정상이라 이름 일치가 먼저이고, 정확한 변환은 상위 2줄 안에 넣어요. Enter는 선택만 해요. ↓ 다음 Enter(또는 Tab)로 AAPL에 GP를 적용해요.

### (e) 종목 없이 `GP` — AAPL을 보고 있는 패널

시작: 패널이 `AAPL US <EQUITY> GIP`를 보여 줘요.

- `G`만 쳤을 때: 기능 줄 GP·GIP가 먼저, 그다음 같은 글자 종목 G(Genpact, 미국)와 G(Gravity, 코인), 그다음 다른 앞부분 순이에요. 한 글자라 Enter는 GP를 선택만 해요. 기능 줄이 강조되면 문맥 칩 `[AAPL US ›]`가 보여요.

```
> [AAPL US ›] GP▌                                       ⏎ 선택: GP · AAPL 가격 차트
 ▸FN     GP     가격 차트           → AAPL US (띄운 종목)        AAPL GP
  EQ·US  GP     GreenPower Motor    나스닥 · 종목은 'GP US'      GP US EQUITY
  EQ·US  [GP]C  Genuine Parts       뉴욕                         GPC US EQUITY
```
- 첫 칸 2글자라 정확으로 치지 않아요. 실제로 GP는 미국 티커이기도 해요.
- 첫 Enter: GP 줄 선택 → 라벨 `⏎ 실행: AAPL 가격 차트 (GP)`. 두 번째 Enter: 패널이 GIP에서 GP로 바뀌어요.
- 더 빠른 길: `GP⇥⏎`(Tab으로 기능을 확정), `AAPL GP⏎`.
- 전문가: 입력 중에는 목록이 안 열려요. Enter를 누를 때 애매함을 따져 목록을 열고 1번을 선택해요. 결과는 같아요.
- 띄운 종목이 없고 연동도 없으면: 두 번째 Enter 뒤 `GP ▌[종목]`, 라벨 `⏎ 종목 필요: GP에 쓸 종목을 입력하세요`, 최근 종목 목록. 이어서 `005930⏎` → `005930 KS <EQUITY> GP`.
- 종목 GP를 원하면 `GP US` 또는 2번 줄.

### (f) `BTC`

시작: 패널이 `005930 KS <EQUITY> GP`를 보여 줘요.

- `B`만 쳤을 때: B로 시작하는 기능이 없어서 종목만 보여요. 같은 글자 B(Barrick Mining, 미국)가 맨 앞, 그다음 인기도 순(BTC, BAC…)이에요. 흐린 글씨는 후보 `« US EQUITY¦ GP»`이고, 한 글자라 Enter는 선택만 해요.

```
> BTC▌‹ CRYPTO¦ GP›                                     ⏎ 실행: 비트코인(BTC/USDT) 가격 차트 (GP)
 ▸CRY    BTC  비트코인                        바이낸스 · USDT   BTC CRYPTO
  EQ·US  BTC  Grayscale Bitcoin Mini Trust    ETF               BTC US EQUITY
 종목 ✓ BTC → 코인(BTC/USDT)으로 읽었어요 · 미국 ETF는 ↓ 또는 BTC US
```
- 두 줄 모두 정확 일치예요. 덮어쓰기 표(BTC → CRYPTO)에 있어서 코인으로 정해지고, 흐린 글씨가 확정이에요.
- 패널의 GP는 종목용이고 코인에도 맞아서 그대로 써요.
- Enter → `BTC <CRYPTO> GP`. Tab → `BTC CRYPTO ▌‹GP›`, 기능 목록(GP, GIP).
- 변형:
  - `BTC US`, `BTC EQ` → ETF.
  - ↓⏎로 ETF를 한 번 고르면 그때만 ETF를 열어요. 두 번째로 고르면 알림: `이제 BTC⏎는 BTC US(ETF)로 열려요 · [되돌리기]`.
  - `비트코인`, `btcusdt`, `btc/usdt` → `BTC CRYPTO`. `ETHBTC` → `코인은 USDT 마켓만 지원해요 → ETH CRYPTO`.
  - `ㅠㅅㅊ`(한글 모드) → 변환 줄 BTC. 첫 칸이라 선택만.
  - `CVX⏎` → 덮어쓰기 표에 없어서 셰브론과 Convex 두 줄, 선택만(§7.1).

### (g) `WEI`

시작: 패널이 `AAPL US <EQUITY> GP`를 보여 줘요.

- `W`만 쳤을 때: 기능 줄 WEI가 먼저, 그다음 W(Wayfair, 미국)와 W(Wormhole, 코인). 한 글자라 Enter는 WEI를 선택만 해요.

```
> WEI▌                                                  ⏎ 실행: 세계 지수 (종목 불필요)
 ▸FN  WEI  세계 지수   미주·유럽·아시아 주요 지수        WEI
 기능 ✓ WEI │ 종목 필요 없음 — AAPL은 이 패널에 그대로 남아요
```
- 3글자 정확 기능 코드이고 같은 글자 종목이 없어서 바로 실행돼요. 문맥 칩은 없어요.
- 실행 뒤 패널에 흐리게 `띄운 종목: AAPL US`가 남아요. `GP⏎⏎`로 AAPL 차트가 돌아오고, Alt+←(Mac ⌘[, 확인 필요)로 뒤로 가도 돼요.
- 연동 패널에서 WEI는 그룹 종목을 바꾸지 않아요.
- 변형: `지수⏎`(정확한 키워드라 바로 실행). `ㅈ댜`(한글 모드) → `ㅈ댜 → WEI` 변환 줄이 상위 2줄에, 선택만. `005930 WEI` → WEI 실행, 005930을 띄운 종목으로(연동 그룹에도 퍼짐).

## 6. 찾기와 순서 규칙

### 6.1 색인

- **레코드마다**: id, 자산군, 시장, 거래소, 코드 키(코드 + `BTCUSDT`, `BRKB` 같은 별칭), 한글 이름, 영문 이름, 자모 문자열, 초성 문자열(한글이 아닌 글자는 남김: `SKㅎㅇㄴㅅ`), 한글 이름을 영문 자판으로 친 키(삼성전자 → `tkatjdwjswk`), 영문 단어 시작, 표시(PREF 등), 인기도.
- **출처**
  - KRX: KIS 종목 마스터. KS·KQ, ETF, ETN, REIT 포함, ELW는 빼요. 파일 형식과 칸 구성은 확인 필요.
  - 미국: KIS 해외 마스터(nas·nys·ams, cp949 탭 구분). KIS 공개 코드 기준으로 'Korea name', 'DR 여부', 증권 종류 칸이 있어요. 한글 이름이 얼마나 채워져 있는지는 확인 필요. 워런트는 빼요(기본값).
  - 코인: 바이낸스 exchangeInfo의 USDT 현물 쌍. 법정화폐·스테이블코인 기초 자산(EUR, EURI, USDC, FDUSD, TUSD, USDE, USD1, RLUSD, XUSD, BFUSD 등)과 영문·숫자가 아닌 기초 자산(`牛来` 등)은 빼요. 이 제외 목록은 색인을 만들 때 검토해요.
  - 바이낸스 목록에는 주식 티커 뒤에 B가 붙은 듯한 기초 자산(GOOGLB, BABAB 등)도 있어요. 성격과 포함 여부 확인 필요.
  - 환율·지수: 정해 둔 목록. 주요 코인 약 30개의 한글 이름.
- 색인은 화면과 다른 별도 프로세스에서 만들어요. 앱에 사본을 넣어 두어서, 첫 실행 때 인터넷이 없어도 종목 검색(자동완성)은 돼요. 시세는 연결이 필요해요.

### 6.2 검색어 정리와 분류

- 해석기 안에서만 유니코드 정규화(NFC, 전각 문자는 NFKC). 앞뒤 공백·꺾쇠 제거, 대소문자 무시(대문자는 화면에만 그렇게 보여요). 코드 키는 구분자를 빼고 비교해요(`BRK.B`, `BRK/B`, `BRK-B` → `BRKB`). 이름은 공백 없이 비교해요. 초성 검색어의 겹자음(ㄳ, ㄵ, ㄺ…)은 나눠요.
- 분류: 코드 모양, 영문, 한글 음절, 자모만(초성), 섞임.
- KRX 코드는 "6자리 숫자" 모양이 아니라 **마스터 조회로** 판별해요(영문자가 섞인 코드가 있는지 확인 필요).
- 숫자로 시작하는 코인(`1INCH`, `1000SATS`, `0G`, `2Z`)도 코드로 분류해요. `0G`·`2Z`는 KRX 코드 앞부분과 겹칠 수 있어서 둘 다 보여 주고 선택만 해요.

### 6.3 짧은 입력 규칙

- **한 글자 입력**은 어느 칸에서도 "정확"이나 "함축"이 되지 않아요.
- **줄 첫머리의 영문·숫자 2글자 이하**도 마찬가지예요.
- 이유: G, B, W, C, F, T는 실제 미국 티커이고, G·W·C·F·T는 바이낸스 코인이기도 해요. GS, KT, KB는 미국 티커이면서 한국 회사 이름이에요. 짧은 입력을 바로 실행하면 첫 글자마다 엉뚱한 종목이 열려요.
- 짧은 입력은 앞부분으로 순위를 매기고, Enter는 선택만 해요.
- 그래서 지금 규칙대로면 `GP⏎`(줄 첫머리 2글자)와 `005930 N`(v0.2 뉴스, 한 글자)도 Enter를 두 번 눌러야 해요.
- **정확한 기능 코드를 이 규칙의 예외로 둘지(줄 첫머리 `GP`·`FA`, 종목 뒤 한 글자 `N`)는 미정**이에요 — [07](07-open-questions.md) 참고.
  - (가) 지금 규칙대로 짧은 입력은 모두 선택만 → `GP⏎⏎`
  - (나) 줄 첫머리 `GP⏎`·`FA⏎`와 종목 뒤 `005930 N⏎`은 Enter 한 번에 실행. 같은 이름의 종목은 `GP US`처럼 시장을 붙여요. 줄 첫머리 한 글자(`G`, `B`, `N`)는 계속 선택만 해요.
  - 제안은 (나)예요. 블룸버그 숙련자가 자주 치는 형태이고, ⏎ 라벨이 실행 전에 무엇을 할지 보여줘요.
  - 이 문서의 예시는 아직 (가) 기준이에요.

### 6.4 순위 등급(T0~T9)

후보 목록의 줄은 얼마나 잘 맞았는지에 따라 T0~T9 등급을 받아요. 숫자가 작을수록 잘 맞은 것이라 목록 위에 나와요(T0 = 글자 그대로 일치, T8 = 한/영을 잘못 놓고 친 것). 한 줄의 등급은 그 줄의 가장 좋은 일치로 정해요.

| 등급 | 일치 | 예 |
|---|---|---|
| T0 | 정확: 코드·티커·심볼 별칭·기능 코드·한국어 키워드·사용자 별칭(v0.2). 짧은 입력은 빼요 | `005930`, `AAPL`, `BTCUSDT`, `WEI`, `차트` |
| T1 | 정확한 전체 이름(한·영, 공백 무시). 여러 단어 이름은 가장 긴 것부터 | `삼성전자`, `apple`, `equity residential` |
| T2 | 기능 코드·키워드 앞부분 | `G` → GP, GIP |
| T3 | 코드·티커 앞부분. 짧아서 정확으로 치지 않은 같은 글자 종목이 맨 앞 | `0059` → 005930, `G` → G |
| T4 | 이름 앞부분: 한글은 음절 단위, 영문은 단어 시작 | `삼성`, `appl` |
| T5 | 한글 이름 앞부분(자모 단위, 마지막 음절 미완성). 조합 중에는 T4와 같은 순위 | `삼성저` → 삼성전자 |
| T6 | 초성(전체 일치가 앞부분 일치보다 먼저), 음절 + 초성 | `ㅅㅅㅈㅈ`, `삼ㅅㅈㅈ` |
| T7 | 음절·단어 경계에서 시작하는 부분 일치, 앞자리 0이 빠진 코드 | `전자` → LG전자, `5930` → 005930 |
| T8 | 한/영 변환(양방향) | `ㅁ메ㅣ` → AAPL, `tkatjd` → 삼성전자 |
| T9 (v0.2) | 오타 허용: 4글자 이상 영문 이름과 기능 코드, 한 글자 차이, 위 결과가 3개 미만일 때만. 코드·티커에는 안 써요 | `apel` → Apple |

- 한국어 키워드는 완성된 음절이 있거나 초성이 2글자 이상일 때만 T2에 들어가요. `ㅅ` 하나로 `설정`이 맨 위에 오지 않게 하려는 거예요.
- 영문 머리글자 일치(acronym)는 v0.2예요.

### 6.5 등급보다 먼저 적용하는 배치 규칙

1. T0이 하나면 1번 줄이에요. 여러 개면 겹침 규칙(§7)을 따라요.
2. **기억된 선택(↺)** 은 애매한 목록에서만 순서를 바꿔요. 그 검색어로 지난번 고른 줄을 1번으로 올려요. 정확 일치와 겹침 기본값은 바꾸지 않아요. Enter는 여전히 선택만 해요.
3. 첫 칸에서는 기능 줄이 같은 등급의 종목 줄보다 먼저예요(최대 3줄).
4. **시장·자산군·기능 칸의 한글**은 키워드, 초성, 한/영 변환을 함께 찾아요. 순서: 정확한 키워드 → 정확한 변환 → 앞부분 일치(선택만, 기능 칸 순서 §6.7).
5. **첫 칸의 한글**은 한글 이름이 먼저예요. 변환 줄은 변환 결과가 2글자 이상이면서 기능 코드·티커와 같거나, 3글자 이상 코드의 앞부분일 때만 보여요. 정확한 변환은 상위 2줄 안(이름 일치가 없으면 1번)에 넣어요. 늘 선택만 해요.
6. **우선주**는 보통주 바로 아래예요. 보통주 위로 가지 않아요(초성·자모 목록도 같아요).
7. ETN·SPAC은 같은 등급 안에서 아래로 내려요.

### 6.6 같은 등급 안의 순서

점수 = 0.5 × 사용 점수 + 0.3 × 인기도 + 0.2 × 문맥 (각각 0–1로 맞춤). 이 식과 무게는 근거 없이 일단 정한 **기본값(바꿀 수 있음)** 이에요.

- **사용 점수**: 이 종목을 쓴 최근 20번 각각에 0.5^(지난 날수 ÷ 7)을 더한 값, 상한 있음.
- **인기도**: 자산군 안의 순위를 백분위로 바꿔 자산군끼리 비교해요. KRX는 시가총액(마스터에 칸이 있는지 확인 필요), 미국은 앱에 넣는 유동성 목록과 앱에서 본 거래량(목록 출처 확인 필요), 코인은 24시간 거래대금, 정해 둔 목록은 그 순서.
- **문맥**: 패널 종목과 같은 자산군 +0.5, 같은 시장 +0.25, 관심종목(MON)에 있으면 +0.25.
- **마지막 동점**: 짧은 코드 먼저, 그다음 id.
- 바로바로 같은 규칙으로 계산하니 순서가 깜빡이지 않아요.

### 6.7 기능 칸의 순서

1. 정확한 코드·키워드·변환
2. 패널의 지금 기능(종목용이고 이 자산군에 맞으면)
3. 이 자산군에서 가장 자주 쓴 기능
4. 기본 순서([03 기능 코드](03-functions.md)): 주식 GP, GIP, DES, N, COMP, FA / 코인 GP, GIP, COMP / 환율 GP, GIP, COMP / 지수 GP, GIP, COMP. GIP는 데이터 소스가 분봉을 줄 때만 보여요(§3.4)

종목이 필요 없는 기능(WEI, FXC…)은 미리 늘어놓지 않고, 입력과 일치할 때만 아래쪽에 보여요.

## 7. 겹치는 이름(충돌) 처리

2026년 10월 조사 시점의 바이낸스·미국 상장 목록으로 보면, 바이낸스에서 거래 중인 USDT 기초 자산은 약 511개이고 그중 약 113개가 미국 티커와 글자가 같아요(C, F, T, CVX, DASH, LINK, COMP, BTC, ETH 등). 처음엔 "지수 > 코인 > 환율 > 미국 주식" 순으로 늘 이기게 하는 방법도 생각했지만, 겹치는 이름이 너무 많아서 쓰지 않아요.

### 7.1 같은 글자가 여러 자산군에 있을 때

위에서부터 처음 맞는 것으로 정해요.

1. **시장이나 자산군을 직접 쓰면** 그것으로 정해요(`BTC US`, `BTC EQ`).
2. **검토된 덮어쓰기 표**: BTC, ETH, SOL, XRP → CRYPTO. 통화 코드(ISO-4217: USD, EUR, JPY…)는 CURNCY로 넣는 것을 제안해요(`USD`는 미국 ETF이기도 해요). 표는 사람이 검토해 앱과 함께 배포해요. 기본값(바꿀 수 있음).
3. **사용자가 정한 기본값**(§7.4).
4. **그 밖에는 처음부터 실행하지 않아요.** Enter는 1번 줄을 선택만 하고, 두 줄을 모두 보여 줘요. 순서는 자산군을 가로지른 인기도(§6.6)예요.

진행 표시에 어느 뜻으로 읽었는지 늘 적어요. 다른 뜻은 늘 바로 아래 줄에 있어요.

예: `BTC⏎` → 표에 있어서 코인, 바로 실행. `CVX⏎` → 셰브론(미국)과 Convex(코인) 두 줄, 선택만. `C⏎` → 한 글자라 어차피 선택만.

### 7.2 한국 회사 이름과 미국 티커

- `GS`, `KT`, `KB`는 미국 티커예요(골드만삭스, KT ADR, KB금융 ADR). 한국 사용자에게는 한국 회사 이름이에요. 한 시장의 정확한 티커와 다른 시장의 정확한 이름이 같으면 겹침으로 보고 선택만 해요. (이 셋은 2글자라 짧은 입력 규칙으로도 선택만이에요.)
- ADR에는 `ADR` 표시를 붙이고, 설명 창에서 KRX 종목과 서로 이어요(KIS 해외 마스터의 'DR 여부').

### 7.3 입력한 시장이 먼저 걸러요

- 시장을 쓰면 그 시장 안에서 먼저 찾아요. `GS KS` → 코스피의 GS(GS홀딩스). 골드만삭스가 아니에요.
- 시장 교정은 **입력한 시장에서 아무것도 못 찾을 때만** 해요. `005930 KQ` → KS로 교정(주황 점선 밑줄, 라벨에 표시, 실행).

### 7.4 기억된 선택과 사용자가 정한 기본값

- 기억된 선택(↺)은 애매한 목록의 순서만 바꿔요(§6.5). 정확 일치 겹침의 기본값을 바꾸려면:
  - 같은 입력에서 1번이 아닌 같은 줄을 **두 번** 고르거나(기본값),
  - 설명 창의 `기본값으로` 버튼을 눌러요.
  - 바뀌면 알림이 떠요: `이제 BTC⏎는 BTC US(ETF)로 열려요 · [되돌리기]`.
- 그 뒤 ⏎ 라벨에 `(내가 정한 기본값 ↺)`가 붙어요.
- 지우기: ↺ 줄이 강조돼 있을 때 Shift+Delete, 또는 설정의 `기억된 선택 초기화`.

### 7.5 기능·명령 단어와 티커 (줄 첫머리)

- **3글자 이상이면 기능**이에요(기본값, 블룸버그 동작 추정, 확인 필요). `FXC`, `DES`(v0.2), `COMP`(v0.2), `ECO`·`GRID`(v0.3)는 모두 미국 티커이기도 해요. 종목을 원하면 `FXC US`처럼 시장을 붙이거나 2번 줄을 골라요.
- **2글자 이하**는 짧은 입력 규칙으로 선택만 해요. 기능 줄이 1번이에요(`GP`, `FA`). 정확한 기능 코드를 예외로 둘지는 미정이에요(§6.3).
- **끝의 GO**: 직접 치거나 붙여넣은 `GO`·`<GO>`는 기능 바로 뒤, 줄 끝일 때만 지워요. 그래서 `005930 KS <EQUITY> GP <GO>`를 그대로 따라 쳐도 돼요. `GO`는 미국 티커(Grocery Outlet)이기도 해서, `GO`만 치면 종목 검색이에요(2글자라 선택만).
- **HELP**: `HELP⏎`가 도움말인지 미국 종목 HELP(Helus Pharma)인지 미정 — 07-open-questions.md 참고. 제안: 도움말, 종목은 `HELP US`.

### 7.6 여러 단어 이름과 예약어

- Equity Residential, Grid Dynamics, Okeanis Eco처럼 이름에 EQUITY, GRID, ECO가 들어 있어요.
- 여러 단어는 **가장 긴 이름 일치를 먼저** 봐요. 예약어로 읽는 뜻은 2번 줄로 남겨요.
- 영문 이름은 그 자리에서 유효한 단어가 나올 때까지 한 이름으로 읽어요(`bank of america GP`).

### 7.7 겹침 표와 테스트

- 색인을 만들 때 기능·시장·자산군 단어와 티커·코인·이름 사이의 겹침을 모두 표로 뽑아요. 이 표로 답이 정해진 해석기 테스트를 만들고, 도움말 페이지에도 실어요.
- 처음 넣을 실제 겹침:
  - 기능·명령 단어: `DES`, `FXC`, `GRID`(미국 ETF), `ECO`, `FA`, `COMP`, `GO`, `GP`, `HELP`
  - 자산군·시장 단어: `EQ`, `IDX`, `CRY`, `IND`, `UP`, `UA`, `UN`, `AMS`, `BN`, `USD`
  - 코인과 미국 티커: `C`, `F`, `T`, `G`, `W`, `CVX`, `DASH`, `LINK`, `BTC`, `ETH`
  - 한국 이름과 미국 티커: `GS`, `KT`, `KB`

## 8. 한글 입력 처리

> 개발자용 세부 규칙이에요. 요약하면 ① 한글을 치는 도중 누른 Tab·Enter·화살표도 딱 한 번, 의도한 대로 동작해요. ② 한글 모드로 잘못 친 영문 코드(`헤` → GP)를 알아봐요. ③ 앱이 운영체제의 한/영 상태를 바꾸지 않아요.

배경: 한국어 IME에서는 Enter·Tab·화살표가 "음절 마무리"와 "원래 키 동작"을 둘 다 해요. 일본어처럼 첫 Enter가 확정만 하지 않아요. 그래서 사용자는 Enter 한 번에 음절이 끝나고 명령도 실행되기를 기대해요.

### 8.1 규칙

- **K1 다시 계산**: input 이벤트마다(조합 중 포함) 목록을 다시 계산하고, compositionend 뒤에 한 번 더 해요.
- **K2 조합 중 키 판별**: `isComposing`이 참이거나 `keyCode`가 229면 조합 중 키예요. React에서는 `nativeEvent`에서 읽어요.
- **K3 미뤄 둔 의도** (Tab, Enter, ↑↓, PgUp·PgDn, Esc, 자산군 단축키)
  1. 조합 중 keydown에서는 Tab만 기본 동작을 막아요(막아도 음절 마무리에 문제가 없는지 확인 필요). 의도를 기록해요: 번호, 종류, 물리 키(`e.code`), 대상 줄의 **id**. 화살표면 "옮겨 갈 줄의 id", Tab·Enter면 그때 강조된 줄의 id예요. 몇 번째 줄인지는 적지 않아요. 음절이 끝나면 목록이 다시 정렬되기 때문이에요.
  2. 조합 중 표시는 compositionend에서 바로 내려요. 한 프레임 미루지 않아요(Safari용 지연 방식은 Chromium에서 한국어 Enter를 삼킬 수 있다는 가설, 확인 필요).
  3. 입력칸에 쓰는 일(채우기, `헤`→`GP`)은 compositionend 다음에 오는 input 이벤트 뒤에 해요. 이 순서는 확인 필요.
  4. 그다음 처음 오는 진짜 keydown(조합 아님)에서 의도를 **딱 한 번** 실행해요. 다른 키가 오면 의도를 버리고 그 키를 처리해요.
  5. 대체 시간(시작값 50ms, 확인 필요) 안에 진짜 keydown이 안 오면 의도를 실행하고 "사용함"으로 표시해요. 그 뒤 같은 `e.code`의 keydown은 약 300ms 동안 또는 keyup까지 삼켜요. 늦게 온 진짜 Enter가 "두 번째 Enter"가 되어, 선택만 했어야 할 것을 실행하는 일을 막아요.
  6. Enter·Tab의 반복 입력(`e.repeat`)은 무시해요.
  7. 기록한 줄 id가 새 목록에 없으면 받아들이지 않고, 새 목록 1번을 강조(선택 없음)만 해요.
  8. 이런 경우를 개발용 이벤트 기록기에 남겨요.
- **K4 조합 중에는 쓰지 않기**: 입력값을 바꾸지 않아요. 대문자는 화면에만. 고쳐 쓰기는 Ctrl+Z 한 번으로 되돌려요.
- **K5 목록이 바뀌면** 강조를 1번·선택 없음으로 되돌려요(조합 중 포함). 다른 앱(Cursor)에서 보고된 "엉뚱한 줄이 선택되는" 버그를 막아요. K3의 id 적용만 예외예요.
- **K6** 조합 중에는 흐린 글씨를 숨기고 목록은 유지해요. **K7** 조합 중에는 자모 일치를 음절 일치와 같은 순위로 둬요. "사망"을 치는 중에 "삼"이 잠깐 보이기 때문이에요.
- **K8 마우스**: mousedown에서 처리하고 기본 동작을 막아 포커스를 지켜요. 조합 중 클릭은 음절이 끝나지 않을 수 있어요(포커스가 그대로라 compositionend가 안 올 수 있음). 대책 후보는 `blur()` 후 `focus()`로 음절을 마무리하고 대체 시간을 두는 것이에요. 동작 확인 필요. 더블클릭은 첫 클릭 때 잡은 줄 id로 처리해요(첫 클릭이 목록을 기능 목록으로 바꾸기 때문).
- **K9 물리 키**: 조합 중 `e.key`는 "Process"나 자모일 수 있어요. Enter와 NumpadEnter는 같게 다뤄요.
- **K10 `[한]` 배지**: 조합 이벤트로만 켜고, 영문 글자 입력으로만 꺼요. 숫자는 한글 모드에서도 조합 없이 들어가서 배지를 바꾸지 않아요. Windows의 HangulMode 키(`Lang1`)를 누르면 "상태 모름"(배지를 흐리게)으로 둬요.
- **K11 OS 입력 모드는 읽지도 바꾸지도 않아요.** 웹에서 쓸 방법이 없고(CSS `ime-mode` 미지원), 네이티브 전환은 시스템 전체에 영향을 줘요. 대신 앱 안에서 변환해요(§8.2). "커맨드 라인에 포커스가 오면 영문으로" 옵션은 v0.2에서 안전하다는 근거가 있을 때만 검토해요(확인 필요).
- **K12 명령 팔레트**는 별도 창이 아니라 창 안의 겹침 화면으로 그려요. macOS에서 코드로 띄운 창의 한글 조합이 깨진다는 보고가 있지만 원인은 가설이에요(확인 필요). 떼어낸 창은 열자마자 한글 입력을 시험해요.
- **K13 시험**
  - 개발 빌드에 keydown·composition·input 이벤트 기록기를 넣어요. 실제 기기에서 기록한 순서를 단위 테스트로 만들어요.
  - 수동 시험 표: {Win11 새 Microsoft IME, Win11 이전 버전 IME} × {Tab, Enter, 화살표, Esc, 클릭, 더블클릭} × {조합 중, 음절 끝남}. 떼어낸 창과 팔레트는 열자마자. 입력칸 구현 두 안(§9) 모두.
  - macOS 2벌식은 Mac 기기를 쓸 수 있을 때 같은 표로 확인해요. 그 전에는 확인하지 못한 채로 남아요.
  - Electron을 올릴 때마다 다시 해요.
  - Win11 새 IME가 마지막 음절을 중복 입력한다는 보고(블로그 하나뿐)는 확인 필요. 사실이면 앱 밖의 문제로 안내 문서에 적어요.

### 8.2 한/영 변환

| 칸 | 규칙 |
|---|---|
| 시장·자산군·기능 (닫힌 칸) | 키워드·초성과 함께 변환도 찾아요(한글 → 영문 자판 → 대문자). 정확한 변환은 실행 가능(교정 표시) |
| 종목, 한글로 입력 | 이름이 먼저. 변환 줄은 §6.5의 5번 조건일 때만. 선택만 |
| 종목, 영문으로 입력(3글자 이상, 결과 3개 미만) | 한글 이름의 영문 자판 키도 찾아 `영→한` 줄로 보여 줘요 |
| 공통 | 변환된 **종목**은 절대 몰래 바꾸지 않아요. 사용자가 골라야 해요. 앱은 어떤 자판을 쓰는지 알 수 없어서, 세벌식 등 다른 자판에서는 한/영 교정이 맞지 않을 수 있어요. 그때는 설정에서 `한/영 실수 교정`을 끄면 돼요 |

한글 모드로 친 코드의 예(두벌식, 소문자): GP→`헤`, GIP→`햐ㅔ`, WEI→`ㅈ댜`, FXC→`ㄹㅌㅊ`, CRYP→`ㅊ교ㅔ`, EQUITY→`ㄷ벼ㅑ쇼`, KS→`ㅏㄴ`, AAPL→`ㅁ메ㅣ`, BTC→`ㅠㅅㅊ`, GO→`해`.

- Shift는 두벌식에서 Q·W·E·R·T·O·P만 바꿔요. 그래서 한글 → 영문 방향은 대소문자만 잃고 결과가 하나로 정해져요.
- 설정의 `한/영 실수 교정`을 끄면 변환 줄과 자동 교정이 모두 꺼져요. 그때 기능 칸의 `헤`는 알 수 없는 기능(✗)이고, 진행 표시가 한/영 키를 확인하라고 알려 줘요.

## 9. 입력칸 구현과 되돌리기

> 개발자용 세부 사항이에요. 요약하면 노란 칩·흐린 글씨·밑줄을 그리려면 일반 입력칸으로는 부족해서, 두 가지 구현 방법을 시제품으로 시험해 고르고, 어느 쪽이든 Ctrl+Z 되돌리기가 제대로 되게 해요.

### 9.1 두 안을 시험해서 골라요 (확인 필요)

일반 입력칸(`<input>`)은 글자 일부에 배경·밑줄을 그릴 수 없어요. 노란 칩, 주황 점선 밑줄(조합 중인 `헤`에도), 빨간 밑줄, 연한 토큰, 줄 안의 흐린 글씨가 모두 필요해요.

| 안 | 방식 | 주의할 점 |
|---|---|---|
| (a) 겹쳐 그리기 | 배경이 투명한 `<input>` 아래에, 같은 글꼴·여백의 거울 div가 장식과 흐린 글씨를 그려요 | 가로 스크롤 위치 맞추기, 화면 배율이 바뀔 때 다시 맞추기. 글자색을 투명(`color: transparent`)으로 하면 안 돼요. IME 조합 글자가 안 보여요 |
| (b) CodeMirror 6 | 한 줄 편집기로 써요 | 장식, 조합을 아는 편집, 자체 되돌리기 기록이 있어요. 크기와 학습 비용 |

두 안 모두 §8.1 K13의 시험 표를 통과해야 해요. 통과한 것 중에서 골라요. 어느 쪽이든 React에서 값을 제어하지 않는(uncontrolled) 방식으로 써요.

### 9.2 되돌리기

- 코드가 `input.value`에 직접 쓰면 Chromium의 기본 되돌리기 기록이 지워져요. 그러면 "채우기 한 번 = 되돌리기 한 번", "Esc로 지운 줄을 Mod+Z로 복구"가 깨져요.
- (a)안: 선택 범위에 `document.execCommand('insertText')`로 써서 기본 기록을 살리거나, 자체 되돌리기 기록을 둬요(Mod+Z, Mod+Shift+Z, Ctrl+Y와 `beforeinput`의 `historyUndo`·`historyRedo`를 가로챔). (b)안: CodeMirror의 기록을 써요.
- macOS에서는 메뉴의 Edit 역할을 남겨요. 없으면 입력칸에서 ⌘C·⌘V·⌘Z가 안 돼요.
- Backspace는 보통처럼 한 글자만 지워요. 채우기를 되돌리는 건 Mod+Z예요. 예외는 자동 교정(`헤`→`GP`, `KQ`→`KS`) 바로 다음의 Backspace로, 원래 글자로 되돌려요.
- 연한 토큰(자동으로 채운 시장·자산군)이 무엇인지 따로 저장하지 않아요. 해석할 때마다 글자에서 다시 계산해요.
- Tab이나 클릭으로 고른 뜻은 그 토큰의 글자가 그대로인 동안만 유지돼요. 글자를 고치면 사라져요.

## 10. 포커스와 단축키

### 10.1 포커스 모드 두 가지

| 모드 | 들어가는 법 | 표시 |
|---|---|---|
| 커맨드 라인 (기본) | 패널이 활성화되면 | 입력줄 커서 |
| 패널 본문 | 빈 줄에서 Esc, 언제나 F6, Ctrl+↓(Windows) | 본문에 주황 안쪽 테두리 |

- 본문 모드에서는 MON 행을 ↑↓로 옮기고, 표를 복사하고, 나중의 PORT·ALRT 입력 양식을 써요.
- 커맨드 라인으로 돌아가기: Esc, Mod+L, 영문 글자·숫자 키(그 글자부터 입력돼요. 본문의 입력 양식에 포커스가 있을 때는 제외). 한글 키도 돌아가지만 첫 자모가 사라질 수 있어서 힌트를 보여 줘요. 첫 자모가 사라질 수 있는 건 본문 모드에서 바로 한글을 칠 때뿐이고, 이 경우는 감수해요.
- 빈 줄이고 목록이 없으면 Tab·Shift+Tab은 보통처럼 포커스를 옮겨요(F6은 늘 커맨드 라인 ↔ 패널 본문). 입문의 시작 목록이 열려 있을 때만 예외로, Tab이 강조된 줄을 채워요.
- 이렇게 해서 키보드가 커맨드 라인에 갇히지 않게 해요(WCAG 2.1.2). 패널 전환은 Ctrl+Tab, Mod+1…9예요.
- Mac에서 Ctrl+↓는 시스템 단축키와 겹칠 수 있어요. Esc·F6만 쓸지는 Mac 기기를 쓸 수 있을 때 확인해요.

| Shift+Enter / Ctrl+Enter | Shift+Return / ⌘Return | 실행 준비 (v0.2) | 옆 새 패널 / 새로 떼어낸 창에서 실행 |

| 숫자 + Enter | 같음 | 메뉴 페이지만 (v0.2) | 번호 항목 고르기. 후보 목록에서는 안 써요(숫자는 KRX 코드) |
| 기록 검색 | — | v0.2 | 단축키 미정 — 07-open-questions.md 참고. Ctrl+R은 Electron 새로고침과 겹쳐요 |

- 자산군 단축키를 Mod+Shift로 한 이유: 그냥 Mod+글자는 앱 명령용으로 남기고, Mac의 Option+글자는 악센트 입력(데드 키)이 될 수 있어서예요(확인 필요). 기본 입력 방법은 단어(`EQ`, `CRY`, `CUR`, `IDX`)예요.

### 10.3 Electron 키 충돌

기본 메뉴를 쓰지 않고, 단축키 목록을 직접 정한 메뉴를 만들어요. 아래 기본 메뉴 내용은 우리가 쓸 Electron 버전에서 확인 필요예요.

| 키 | Electron 기본 메뉴 | 처리 |
|---|---|---|
| Ctrl+R, Ctrl+Shift+R | 새로고침 | 배포판에서 빼요. 기록 검색에 Ctrl+R을 쓸지는 이걸 뺀 뒤 정해요 |
| Ctrl+Shift+I | 개발자 도구 | 배포판에서 빼요(우리 INDEX 단축키). 개발 빌드는 다른 키로 옮겨요 |
| F11 (Windows) | 전체 화면 | 직접 정한 목록에서 결정해요. v0.2 F키 모드와 겹쳐요 |
| Ctrl+W | 창 닫기 | 빼는 것을 제안해요. 메인 창을 닫으면 앱이 끝나고, 셸 습관(단어 지우기)으로 누르는 사람도 있어요 |
| Alt 단독, F10 (Windows) | 메뉴 막대로 포커스 | Windows에서는 메뉴 막대를 두지 않고(`setMenu(null)`) 단축키를 화면 쪽에서 처리해요 |
| Mac 메뉴 | App·Edit·Window 역할 | 남겨요. Edit 역할이 없으면 입력칸 복사·붙여넣기·되돌리기가 안 돼요 |

- F5·F12는 기본 메뉴가 묶지 않아서 충돌하지 않아요(F키 모드를 넣을 때 다시 확인).
- Mac의 ⌘W(창 닫기)를 메인 창에서 어떻게 할지 확인 필요(메인 창 닫기 = 앱 종료).

### 10.4 명령 팔레트 (Ctrl+K, Mac ⌘K)

- 같은 엔진이에요. 창 안의 겹침 화면으로 그려요(별도 창 아님).
- 대상은 **팔레트를 연 그 창의 활성 패널**이에요. 다른 모니터의 패널로 명령이 가지 않게 해요.
- 대상 패널 칩을 보여 줘요(`→ 패널 2 · AAPL US GP`). Alt+1…9로 대상을 바꿔요(Mac Option+숫자가 특수 문자 입력과 겹치는지 확인 필요). 팔레트는 줄을 더 많이 보여 줄 수 있어요.

## 11. 도움 수준과 설정

### 11.1 도움 수준

네 가지 도움 수준은 "보이는 것"만 달라요. Tab·Enter가 하는 일은 모든 수준에서 같아요.

| 보이는 것 | 입문 | 표준 | 전문가 | 끔 |
|---|---|---|---|---|
| 후보 목록 | 입력하면 바로 | 입력하면 바로 | Tab·↓·Alt+↓를 누를 때, 또는 애매하거나 오류일 때 | ↓·Alt+↓를 누를 때만 |
| 흐린 글씨 미리보기 | ✓ | ✓ | ✓ | — |
| 기능 설명 | ✓ | ✓ | 코드와 이름만 | — |
| 설명 창 | 자리가 있으면 자동 | F1 또는 Ctrl+/ (Mac ⌘/) | F1 또는 Ctrl+/ (Mac ⌘/) | F1 또는 Ctrl+/ (Mac ⌘/) |
| 진행 표시 | 전체 | 전체 | 메시지만(오류·교정·겹침) | 메시지만(오류·교정·겹침) |
| 키 안내 · 시작 목록 · 팁 · 안 맞는 기능 흐리게 | ✓ | — | — | — |
| ⏎ 라벨 (Enter 결과 표시) | ✓ | ✓ | ✓ | ✓ |

- **전문가**는 입력하는 동안 애매함을 따지지 않아요. Space·Enter·Tab을 누를 때만 따져요. 그래서 앞부분을 칠 때마다 목록이 열리지 않아요.
- **바꾸는 곳**: 설정 창(Ctrl+, / Mac ⌘,, 또는 커맨드 라인에 `설정⏎`·`PDF⏎`, 화면은 [설정 화면](06-settings.md)), 그리고 상태 표시줄의 빠른 전환 `도움: 입문 ▾`.
- **바꾸면 바로** 모든 패널과 떼어낸 창에 적용돼요. 저장 버튼은 없어요.
- **표준 제안**: 입문에서 목록·Tab·화살표 없이 직접 쳐서 Enter 한 번에 실행한 명령이 30개가 되면 `표준으로 바꿀까요? [바꾸기] [그대로]`를 한 번만 물어봐요(v0.1). 수준은 **저절로 바뀌지 않아요.**
- 첫 실행 기본값: 미정 — 07-open-questions.md 참고(제안: 입문).

## 12. 초보자 도움

### 12.1 시작 목록 (입문, 커맨드 라인에 포커스가 오면)

```
 최근
▸ 005930 KS EQUITY GP     삼성전자 가격 차트
  BTC CRYPTO GIP          비트코인 장중 차트
 종목 없이 바로 쓰는 기능
  MON   관심종목        내가 고른 종목 시세 모음
  WEI   세계 지수       주요국 증시 지수
  …     FXC 환율 매트릭스 · CRYP 코인 시세판
 처음이세요?  ? 를 입력하면 명령어 문법 안내
```

- 1번 줄에서 ↑를 누르면 기록(이전 명령)으로 가요.
- `[종목]` 자리 표시: 종목이 필요할 때 보여요. v0.2부터는 `[비교 종목]`(COMP) 같은 인자 자리 표시도 있어요.

### 12.2 팁

- 목록·Tab·화살표의 도움을 받아 실행했다면, 더 짧은 형태를 알려 줘요. 예: `다음엔 005930 GP ⏎ 만 입력해도 돼요`.
- 같은 팁은 최대 3번, `그만 보기`가 있어요. 한/영 팁도 최대 3번. 설정의 `사용 팁`으로 끌 수 있어요.

### 12.4 기능 목록 하나로 모든 문구를

기능 목록([03 기능 코드](03-functions.md))을 하나의 출처로 써요. 항목마다 코드, 한·영 이름, 한 줄 설명, 종목 필요 여부(없음·하나·선택·여러 개), 지원 자산군, 필요한 데이터, 키워드, 인자, 자산군별 기본 순위, 나오는 버전과 완성 여부, 도움말 카드, 비슷한 기능을 적어요. 후보 줄, 도움말 카드, 문법 요약, 오류 메시지, 시작 목록이 모두 여기서 문구를 가져와요.

### 12.5 도움말

- 줄 오른쪽 끝의 **`?` 버튼**(마우스용).
- **F1 또는 Mod+/**: 강조된 줄의 도움말 카드(이름, 하는 일, 종목 필요 여부, 지원 자산군, 예시 `005930 GP ⏎ · AAPL US GP ⏎ · BTC GP ⏎`, 비슷한 기능).
- **문법 요약**: F1을 한 번 더, 빈 줄에 `?`, 또는 `도움말⏎`. Esc로 닫아요.
```
 [종목]   [시장]  [자산군]   [기능]  ⏎
 005930    KS     EQUITY     GP     ⏎   삼성전자 가격 차트
 AAPL      US     EQUITY     GIP    ⏎   애플 장중 차트
 BTC       –      CRYPTO     GP     ⏎   비트코인(USDT) 가격 차트
 –         –      –          WEI    ⏎   세계 지수 (종목 불필요)
 자산군      EQUITY 주식 · CRYPTO 코인 · CURNCY 환율 · INDEX 지수 (EQ · CRY · CUR · IDX)
 시장        KS 코스피 · KQ 코스닥 · US 미국
 키          Tab 자동완성 · ↑↓ 고르기 · ⏎ 실행 · Esc 닫기 · F1 설명 · ↑(빈 줄) 이전 명령
```
- 패널 커맨드 라인에 보이는 지금 명령의 토큰에 마우스를 올리면 뜻을 알려 줘요(`GP = 가격 차트`, `KS = 코스피`). 클릭하면 그 명령을 고칠 수 있게 줄에 넣어요.
- Tab으로 받아들이는 것은 접근성 가이드(APG)의 콤보박스 규칙과 달라요. 일부러 정한 것이고, 도움말에 적어 둬요.

| 상황 | 처리 |
|---|---|
| 비슷한 종목 (005930·005935, ETF·ETN, SPAC) | 표시, 우선주를 보통주 아래로, 설명 창의 "헷갈리기 쉬운 종목" |
| 마스터에 없는 코드 (오늘 상장, 오래된 파일) | `목록에 없는 코드예요 — ⏎로 KIS에서 직접 조회`. 선택한 뒤 두 번째 Enter에 조회. API가 거절하면 패널에 오류 |
| 마스터를 불러오는 중 | 기능과 기록은 완성돼요. 목록에 `종목 목록 불러오는 중…`. 모양이 맞는 코드는 "확인 전"으로 선택만 하고, 두 번째 Enter에 조회 |
| 입력 중 마스터 갱신 | 목록이 닫혀 있고, 선택된 줄이 없고, 입력이 500ms 멈췄을 때만 바꿔요(기본값). 선택된 줄은 id로 유지 |
| 틀린 자산군 (`005930 CRYPTO`) | 잘못됨, 고침을 1번 줄에. 단, 그 자산군에 같은 글자가 있으면(`BTC EQUITY` = ETF) 그 뜻으로 |
| 자산군에 안 맞는 기능 (코인에 FA, 지수에 DES) | 목록에 없음(입문은 흐리게 + 이유). 직접 치면 `FA(재무제표)는 주식 전용이에요. 코인은 GP·GIP를 쓸 수 있어요`, 실행 안 함 |
| 종목 뒤의 종목 불필요 기능 (`005930 WEI`) | WEI 실행, 005930을 띄운 종목으로(연동 그룹에도). 안내: `WEI는 종목 없이 쓰는 기능이에요` |
| 기능 두 개 (`005930 GP GIP`) | `기능은 하나만 쓸 수 있어요`. 고침 줄은 마지막 것을 남겨요. 실행 안 함 |
| 코인 표기 (`ETHBTC`, `ETH/KRW`, `BTCUSDT`, `BTC-USDT`, `XBT`, `USDT`만) | USDT 쌍이 아니면 `코인은 USDT 마켓만 지원해요`(고침 줄 `ETH CRYPTO`). 표기만 다르면 `BTC CRYPTO`로 정리. `USDT`만 치면 `USDT는 기준 통화예요 — 코인 이름과 함께 입력하세요` |
| 거꾸로 된 환율 (`KRWUSD`) | `환율은 USDKRW 방향으로 보여드려요` → `USDKRW CURNCY` |
| 미국 주식 클래스 (`BRK.B`, `BRK-B`) | `BRK/B US` |
| 지원하지 않는 시장 (`VOD LN`) | `지원하지 않는 시장이에요 (KS·KQ·US만)` |
| 명령 전체 붙여넣기 | 목록을 열지 않고 진행 표시로만 확인. 꺾쇠와 끝의 GO 제거. 실행 안 함 |
| `삼성␠` | 고르기 전 토큰(점선 밑줄)으로 남아요. Enter는 선택, Shift+Tab으로 목록 다시 열기 |
| 커서를 줄 가운데로 | 목록이 커서 아래 칸으로 바뀌어요. 뒤 토큰은 다시 확인하고, 안 맞게 된 기능은 지우지 않고 빨간 밑줄 + ✗ |
| 상장폐지 | `DELISTED` 표시, 맨 아래. 기록·관심종목은 계속 열려요 |
| 숫자패드 | 숫자패드 Enter = Enter. NumLock이 꺼져 화살표·페이지 키가 오면 `NumLock이 꺼져 있어요` 힌트 |
| Mac 한글 모드의 백틱 | ₩가 입력된다는 이야기가 있어요(확인 필요). 문법에서 백틱을 쓰지 않아요. `?`는 첫 글자로 예약 |
| 사용자 별칭이 티커를 가림 (v0.2) | 첫 단어에서는 별칭이 이겨요. `SS US`처럼 시장을 붙이면 진짜 티커 |

## 14. 성능, 여러 창, 접근성

> 개발자용 세부 사항이에요. 요약하면 키를 누를 때마다 목록이 사람이 느끼지 못할 만큼 빨리 바뀌어야 하고, 시세가 몰려도 타자가 느려지면 안 되며, 여러 창과 화면 읽기 프로그램에서도 똑같이 동작해야 해요.

### 14.1 성능 목표 (모두 확인 필요)

| 항목 | 목표 |
|---|---|
| 키 하나당 해석·완성 | p95 ≤ 2ms, p99 ≤ 4ms (p95: 100번 중 95번은 이 시간 안에) |
| 키를 누르고 목록이 그려질 때까지 | 한 프레임(≤ 16ms), 지연 타이머 없음 |
| 새 창에서 색인 준비 | ≤ 80ms. 그 전에는 기능·기록만 완성 |
| 색인 전체 다시 만들기(별도 프로세스에서) | ≤ 300ms |

- 조사에서 잰 것은 가짜 이름 2만 개를 단순 검색한 시간(쿼리당 약 0.4–1.4ms)뿐이에요. 실제 KIS 마스터로 레코드 수와 시간을 다시 재요.
- 시세 해석은 화면과 다른 스레드나 프로세스에서 해요. 차트 다시 그리기는 한 프레임에 한 번으로 묶어요.
- 차트가 실시간으로 움직이는 동안 입력 지연을 Event Timing API로 재요.
- 기록한 키 입력을 CI에서 재생해 p95가 목표를 넘으면 실패로 봐요.

### 14.2 여러 창

- 색인은 렌더러 프로세스마다 하나(압축 배열)예요. 같은 프로세스의 떼어낸 창은 함께 써요(떼어낸 창을 만드는 방식에 따라 다르니 확인 필요).
- 기록, 사용 점수, 기억된 선택, 겹침 기본값은 **메인 프로세스만** 써요. 여러 창이 동시에 써서 기록이 사라지는 일을 막아요. 모두 줄 번호가 아니라 id로 저장해요.

### 14.3 화면 읽기 프로그램

- 입력칸: `role=combobox`, `aria-expanded`, `aria-controls`, `aria-activedescendant`(강조된 줄). 줄: `role=option`. `aria-describedby`는 ⏎ 라벨.
- 알림은 **상태가 바뀔 때만**(선택됨, 실행 준비, 오류, 겹침), 약 400ms씩 묶어서 해요. 키마다 진행 표시를 읽게 하지 않아요.
- 떼어낸 창에서는 목록을 그 창의 문서 안에 그리고, 스타일을 복사하고, 키 처리도 창마다 따로 붙여요.

**블룸버그 관례** (우리 규칙은 기본값으로 정해 둠)

**한글 입력** (§8.1 K13의 시험 표로)
7. Windows Chromium의 이벤트 순서: 진짜 keydown이 늘 compositionend 뒤에 오는지, 마지막 input 이벤트가 compositionend 앞인지 뒤인지.
8. 조합 중 Tab(keyCode 229)의 기본 동작을 막아도 음절 마무리가 괜찮은지. 대체 시간 50ms가 적당한지.
9. 조합 중 마우스 클릭을 `blur()`·`focus()`로 마무리하는 방법이 되는지.
10. Safari식 조합 표시 지연이 Chromium에서 한국어 Enter를 삼키는지. 한글 모드에서 Ctrl·⌘+글자의 `e.key`. Chrome 125 회귀(crbug 341846848)와 Electron #32307·#14834의 현재 상태.
11. macOS에서 코드로 띄운 창의 한글 조합 문제(가설, Mac 기기를 쓸 수 있을 때). Win11 새 Microsoft IME의 마지막 음절 중복(블로그 하나뿐).

**구현과 키**
12. 입력칸 구현 (a) 겹쳐 그리기 vs (b) CodeMirror 6.
13. Electron 기본 메뉴의 실제 단축키 목록(쓸 버전), Windows에서 `setMenu(null)` 뒤 Alt·F10 동작.
14. Windows: Ctrl+Shift 언어 전환 단축키와 Ctrl+Shift+글자, 일부 설정의 Shift+Space 한/영 전환, 일부 IME의 Ctrl+Space 언어 전환.
15. Mac(Mac 기기를 쓸 수 있을 때): Option+글자 데드 키, ⌘[·⌘]로 뒤로·앞으로, Ctrl+↓ 시스템 단축키, Option+숫자(팔레트 대상 바꾸기), 메인 창에서 ⌘W, 한글 모드 백틱(₩).
16. 떼어낸 창이 부모 창과 같은 렌더러 프로세스를 쓰는지(색인 공유).
17. 성능 목표 전부(§14.1)를 실제 마스터와 차트 스트리밍 중에.
