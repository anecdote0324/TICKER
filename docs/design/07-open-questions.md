## v0.1을 만든 뒤 실제로 확인할 것

이 개발 환경에서는 한국투자증권 서버에 접속할 수 없고, Windows·Mac 실기기도 없어서 확인하지 못한 것이에요. 정식 `v0.1.0`(11/3)을 낸 뒤에도 남은 것은 여기서 계속 확인하고, 고칠 것이 나오면 `0.1.x`로 내요.

- 한국투자증권 실시간 구독이 첫 연결부터 `MAX SUBSCRIBE OVER`로 거절된 원인. v0.1.0-beta.9에서도 16개 중 3개만 받아 줬고(`wsAccepted 3`, `wsRejected 13`), 10분까지 늘려 다시 해도 같았어요. 앱은 한 벌만 떠 있었어요. 이전 연결의 등록이 한국투자증권 쪽에 남아 있는지, 계정(신규 신청 등)마다 한도가 다른지 확인해요. 이제 장이 닫힌 종목은 구독하지 않아서, 받아 준 자리를 장이 열린 종목이 써요. 다음 미리 보기의 진단 정보로 거절이 남는지 봐요
- 한국투자증권 초당 거래건수: v0.1.0-beta.11에서 초당 2~3건까지 줄었는데도 12분에 초과 102번(`throttles`)이었어요. 다시 보내는 요청이 한도를 거치지 않아 한꺼번에 나간 것이 원인으로 보여서 고쳤어요. 진단 정보의 `budget.perSecond`·`throttles`가 이제 15 근처에서 안정되는지 봐요
- GP 시간봉: 주식일별분봉조회(FHKST03010230)로 국내 시간봉이 받아지고 뒤에서 지난 봉이 채워지는 것, 미국 `NMIN=60` 봉이 정각에 오는 것은 확인했어요(v0.1.0-beta.11). 휴장일에 빈 응답인지(앱은 빈 응답이면 앞 평일로 7일까지 건너뛰어요), 미국 60분봉을 과거 어디까지 주는지, 1년치를 채울 때 걸리는 시간은 더 봐요
- 프랑스 CAC 40(`FR#CAC`)이 장중에 갱신되지 않는지(11/2 런던 장중에 금요일 값 그대로). 앱은 15분 넘게 같은 값이면 `일별`로 표시해요. 다른 코드가 있는지, 지연 시세인지 확인해요
- 다우존스(`.DJI`): 해외지수 마스터에 없고, 현재가 칸이 0으로 왔어요(일봉은 옴). 지금은 가장 최근 일봉 종가를 `일별`로 보여 줘요. 장중 값을 받을 다른 코드가 있는지 확인해요
- 한국투자증권 어댑터 전체: 토큰·실시간 접속키 발급, 국내(H0STCNT0)·미국(HDFSCNT0) 실시간 체결의 칸 순서, 조회 응답의 필드 이름, 분봉 조회를 몇 번 이어서 불러야 하는지. 공식 예제 코드를 기준으로 만들었어요
- Windows 11 한글 IME로 커맨드 라인 시험 표(05 §8.1 K13) 실행, 입력칸 (a)·(b)안 비교
- Electron 45의 OS 보안 저장소(Windows DPAPI, macOS 키체인)로 앱키 저장이 되는지
- Windows 휴대용 실행 파일의 첫 실행 경고, Mac(Apple Silicon) .dmg의 미서명 앱 실행 절차(Windows 설치형은 설치·실행 확인됨)
- 떼어낸 창을 다른 모니터로 옮긴 뒤 다시 켰을 때 위치 복원, 모니터를 뺐을 때 창 모으기
- 화면 탭을 통째로 떼어낸 창: Electron(Windows·Mac)에서 창 닫기가 메인 창으로 돌려놓기로 이어지는지, 다음 실행 때 같은 자리에 다시 열리는지, 그 창에서 한글 조합·패널 크기 조절·끌어 옮기기가 되는지
- 목록에 없는 코드 직접 조회: 국내 상품 기본 정보(CTPF1002R)·해외 상품 기본 정보(CTPF1702R)의 응답 필드(`prdt_abrv_name`, `mket_id_cd`, `prdt_eng_name`)와 거래소 구분 코드
- 한글 입력 기록기(설정 → 커맨드 라인)로 Windows IME에서 Tab·Enter·화살표·클릭·더블클릭 순서를 기록해 테스트로 옮기기. 조합 중 클릭(K8)에서 `blur()`·`focus()`로 음절이 마무리되는지
- 성능: 실제 Windows PC에서 설정 → 정보 → 성능의 커맨드 라인 해석 p95와 16ms를 넘긴 입력 이벤트 수. 한 글자 입력은 개발 PC에서 p95 약 4ms라 목표(2ms)를 넘어요. 실제 PC에서도 타자가 밀리면 한글 부분 일치용 색인 등을 더 만들어요(05 §14.1)
- 실사용 중 16ms를 넘긴 입력 이벤트 수가 계속 늘었고, 가장 길었던 것이 약 136ms였어요(v0.1.0-beta.11). 그때 화면을 붙잡은 것이 차트 그리기인지 시세 갱신인지 봐요
- FXC: 워크스페이스를 불러온 직후 잠깐 앞 값이 보였어요(v0.1.0-beta.11). 불러온 패널이 저장된 값을 먼저 그리는지 봐요
- 미국 장이 닫혀 있을 때 QQQM의 GIP가 비어 있었어요(v0.1.0-beta.11). 진단 정보의 `barSamples`(HHDFS76950200)로 장이 닫힌 뒤 해외 분봉 응답이 오는지 봐요
- 글자 크기(Electron 확대 배율)가 떼어낸 창·차트·후보 목록에 같은 배율로 맞게 걸리는지
- 전체 화면: 실제 Windows에서 F11(메인 창·떼어낸 창), Mac에서 ⌃⌘F가 메뉴의 전체 화면 항목과 두 번 겹쳐 실행되지 않는지, 초록 버튼으로 켠 전체 화면을 ⌃⌘F로 끌 수 있는지. Linux(Xvfb)의 Electron에서는 창마다 켜고 끄는 것을 확인했어요
- Electron 45(Windows·Mac)에서 `node:sqlite`로 분봉·이력 저장이 되는지, 종료할 때 남은 분봉이 저장되는지
- 설치 파일의 종목 목록 사본: GitHub Actions에서 KIS 마스터 서버·Binance에 닿는지, 첫 실행을 인터넷 없이 했을 때 종목 검색이 되는지

## v0.2를 만들면서 실제로 확인할 것

- DES: 주식현재가 시세(FHKST01010100)의 `per`·`pbr`·`eps`·`bps`·`w52_hgpr`·`lstn_stcn`·`hts_frgn_ehrt`와 해외주식 현재가상세(HHDFS76200200)의 `perx`·`h52p`·`shar`·`e_icod`가 실제 계정에서 그 이름과 단위로 오는지. 상태 칸(`mang_issu_cls_code`, `mrkt_warn_cls_code`, `invt_caful_yn`)의 값
- 종목 마스터의 매출액·영업이익이 기준 월까지의 누적인지(반기·분기), 연간인지
- DES: DART 기업개황(`company.json`)의 칸 이름과 `hm_url` 모양(앞에 http가 없을 때)
- N: 실제 DART 인증키로 공시검색(`list.json`)이 오늘 공시를 최신순으로 주는지, 고유번호 파일(`corpCode.xml`) 크기와 받는 시간, 하루 2만 건 한도 안인지(2분마다 1건 + 종목을 열 때 1건). RSS 곳마다 갱신 빈도와 제목에 회사 이름이 얼마나 들어가는지(종목 거르기의 쓸모)
- 커맨드 라인(v0.2): Windows Electron에서 F키 모드의 F8~F11이 화면까지 오는지(F10이 창 메뉴로 가지 않는지), Ctrl+R·Ctrl+Enter가 다른 단축키와 겹치지 않는지
- HMAP·IMAP: 구분별전체시세(FHPUP02140000)의 `bstp_cls_code`가 종목 마스터의 업종 코드(0013, 1028, 2013 같은 4자리)와 같은지, 코스피200(`K2`)에서 섹터 지수가 오는지. 멀티종목 시세가 정말 30종목까지 한 번에 되는지, 장이 닫힌 뒤 값. 업종 지수 일봉 3번 × 업종 수(코스피 약 24개)를 하루에 받는 데 걸리는 시간
- MOST: 국내 거래량·거래대금 순위의 `FID_INPUT_ISCD` `0001`·`1001`이 코스피·코스닥 전체로 걸러지는지, 등락률 순위의 `fid_prc_cls_code`의 뜻, 해외 순위의 `rate`·`diff`가 부호를 담는지, 한 번에 몇 줄이 오는지. 장 시작 전·휴장일에 빈 응답인지

## 개발 전에 실제로 확인할 것

### 한국투자증권 API

- 시세만 받을 때 계좌에 예수금이 필요한지
- 실시간 등록 41건(앱키당, 공식 확인)을 체결과 호가가 함께 쓰는지(호가창을 만들 때)
- REST 호출 한도(실전 초당 약 20건으로 안내됨), 해외주식 REST 한도
- 해외지수·환율(X·KX) 조회의 지연 여부와 분봉 제공 여부. WEI와 시세 흐름 띠에 쓸 국내·해외 지수를 어디까지 받을 수 있는지. 환율은 10초마다 조회해요. 값의 방향(`달러/유로` = 1유로당 달러)은 ECB와 비교해 확인했고, 주말에는 값이 멈춰 있어요(v0.1.0-beta.11). 평일 밤(11/2 23:51~23:55)에 원/달러가 몇 분 안에 바뀌는 것은 확인했어요. 서울 외환시장 낮 시간의 갱신 빈도를 확인해요
- 지수 분봉 제공 여부 (지수에서 GIP를 보여줄지 결정)
- 국내선물옵션: KTB 국채선물이 포함되는지, KOSPI200 야간 시세를 주는지
- 옵션전광판에 내재변동성·그릭스가 들어 있는지
- 장내채권 API가 KRX 일반채권시장만 다루는지
- 해외선물: 무료로 일봉·정산가·미결제약정을 받을 수 있는지, 별도 계좌가 필요한지, CME·SGX 실시간 월 요금
- 종목추정실적·투자의견: 시장 컨센서스인지 KIS 단독 추정인지, 다루는 종목 수와 필드, 이력 길이
- 공매도 잔고 비율 API, 단기과열 지정 종목 목록의 소스
- 해외 권리 정보·해외 순위·해외주식 휴장일 API의 범위
- 재배포 금지 조항 원문
- HTS ID에 `$`나 `@`가 들어 있을 때의 제한. KIS Developers 신청 안내에 나오는 주의 사항이라 신청 전에 확인

### 종목 목록(색인)과 코드

- 국내 종목 마스터 파일: 형식과 칸 구성, 시가총액·상장주식수 칸 유무, 영문자가 섞인 종목코드 유무, 실제 종목 수
- 해외 종목 마스터 파일: 한글 이름이 얼마나 채워져 있는지, ADR 여부와 증권 종류 값
- 미국 종목 인기도 목록을 어디서 가져올지, 자산군끼리 인기도를 어떻게 비교할지
- Binance에 있는, 주식 티커 뒤에 B가 붙은 듯한 종목(GOOGLB, BABAB 등)이 무엇인지, 목록에 넣을지
- K로 시작하는 자체 코드(KINV, KPGM, KCRD, KWRN, KCB, KELS)가 블룸버그 코드와 겹치지 않는지
- 확인하지 못한 블룸버그 니모닉([08](08-bloomberg-coverage.md) §6), DRSK의 실제 설명, 드로잉 도구의 니모닉

### DART·ECOS·KRX·공공데이터

- DART: 하루 호출 한도, 지분공시·임원·타법인출자·채무증권 미상환 잔액 API의 범위
- ECOS: 시장금리 통계표의 항목코드, 호출 한도, 요청당 최대 행 수, KOFR·통안채 시리즈 유무, 한국 지표의 수정치 이력
- KOFR 원천(예탁결제원)에 접근하는 방법
- KOFIA: 최종호가수익률 공표 시점(하루 1회인지 11:30·15:30 두 번인지), 장외 채권 체결 데이터
- 자동 수집이 허용되는지: KOFIA 채권정보센터, KRX 정보데이터시스템, 신용평가사 사이트
- KRX Open API: ETF 일별에 상장좌수·NAV 필드가 있는지(ETF 자금 흐름), 옵션 일별에 내재변동성 필드가 있는지, VKOSPI·금시장 포함 여부, API별 승인 기간
- 공공데이터포털: 금융위원회 채권발행정보 상세, 주식시세정보 데이터셋
- KOSIS 호출 한도, 한국은행·통계청 공표일정의 형식
- ELS 발행 정보 소스(SEIBro 등), Opinet, 조달청 국제원자재가격, 관세청·UN Comtrade, 금융투자협회 펀드 공시

### 해외 데이터

- SEC EDGAR 접근 정책(초당 10건, 연락처 헤더), 13F 데이터셋 주소
- 미국 실적 발표 일정의 무료 소스와 약관. 없으면 SEC 8-K로 발표 뒤에 표시
- 미국 ETF 운용사의 보유 내역 공개 약관 (MEMB 미국 근사)
- FRED 호출 한도, Atlanta Fed 정책금리 확률(MPT)의 접근 방식과 약관, FINRA TRACE 무료 범위, 미국 SDR 공개 데이터
- 각국 정책금리(BIS 등), 영국·독일 금리 커브, 유럽 휴장일 소스, Treasury FiscalData, IMF·OECD·World Bank API 세부
- 한국수출입은행 환율 API의 메뉴와 한도, 네이버 검색 API 하루 한도
- CFTC COT 데이터셋 ID, USDA 농산물 현물, World Bank 월간 원자재 가격
- VKOSPI 소스
- Binance 옵션 공개 API(eapi)로 크립토 옵션 탭(체인·행사가별 IV)을 만들 수 있는지, 과거 IV를 주는지. 안 되면 크립토 옵션 탭은 빼요(Deribit은 쓰지 않아요)

### 환율

- 무료 환율 소스 후보를 실제로 테스트해서 선정 (KIS 환율 조회가 1순위 후보)
- 분봉 제공 여부 (환율에서 GIP를 보여줄지 결정)

### Binance

- 국내에서 일반 주소 접속이 되는지, 시세 전용 주소가 필요한지. 규제 동향도 함께 봐요(CRYP 전체에 걸린 위험)
- USDⓈ-M 선물 공개 API가 국내에서 접속되는지, 막힐 때 쓸 예비 주소가 있는지(시세 전용 주소는 현물용이에요)
- USDT 목록의 거래대금 상위에 코인이 아닌 듯한 기초 자산이 있어요: XAUT(금 토큰), SNDKB·SOXLB처럼 주식 이름에 B가 붙은 것. CRYP 시세판과 검색 목록에 넣을지

### 블룸버그 관례와 같은지

- KQ = 코스닥, UN·UW·UQ·UA·UP·NAS·NYS·AMS를 US로 읽기

- 줄 첫머리의 기능 코드를 기능으로 읽는지

### 한글 입력

Windows 11 새·이전 Microsoft IME로 확인해요. 개발 첫 단계에 키 입력 기록 도구를 먼저 만들어서 실제로 확인해요. macOS 2벌식은 Mac 기기를 쓸 수 있을 때 확인하고, 그 전에는 확인하지 못한 채로 남아요.

- 글자 조합이 끝난 뒤 실제 키 입력 이벤트가 늘 따라오는지, 마지막 입력 이벤트가 그 앞인지 뒤인지
- 조합 중 Tab의 기본 동작을 막아도 글자 마무리가 괜찮은지, 대체 대기 시간 50ms가 적당한지
- 조합 중 마우스 클릭을 했을 때 글자를 강제로 마무리할 수 있는지
- 조합 상태 표시를 한 프레임 늦추는 방식이 Chromium에서 한국어 Enter를 삼키는지
- 한글 모드에서 Ctrl·⌘+글자를 눌렀을 때 어떤 키로 읽히는지
- 알려진 버그의 현재 상태: Chromium 341846848, Electron #32307·#14834
- macOS에서 코드로 띄운 창의 한글 조합 문제 (가설, Mac 기기가 있을 때)
- Windows 11 새 IME의 마지막 음절 중복 (블로그 한 곳의 보고뿐)

### 단축키

- 사용할 Electron 버전의 기본 메뉴 단축키 목록, Windows에서 메뉴를 없앤 뒤 Alt·F10 동작
- Windows: Ctrl+Shift 언어 전환과 Ctrl+Shift+글자가 겹치는지, Shift+Space 한/영 전환, 일부 IME의 Ctrl+Space 언어 전환
- Mac (Mac 기기를 쓸 수 있을 때): Option+글자(악센트 입력), ⌘[·⌘]로 뒤로·앞으로, Ctrl+↓ 시스템 단축키, 명령 팔레트 대상 바꾸기 Option+숫자가 특수 문자 입력과 겹치는지, 메인 창에서 ⌘W(= 앱 종료), 한글 모드의 백틱(₩)

### 여러 창과 성능

- 떼어낸 창이 메인 창과 같은 렌더러 프로세스를 쓰는지 (종목 색인 공유)
- 성능 목표를 실제 종목 마스터로, 차트가 실시간으로 움직이는 중에 측정 (p95: 100번 중 95번은 이 시간 안에)
  - 키 하나당 자동완성 계산 p95 2ms 이하, p99 4ms 이하
  - 목록 그리기 16ms 이하
  - 새 창의 색인 준비 80ms 이하
  - 색인 다시 만들기 300ms 이하
