## 개발 전에 실제로 확인할 것

### 한국투자증권 API

- 시세만 받을 때 계좌에 예수금이 필요한지
- 실시간 구독의 정확한 최대 개수 (예제 코드는 40개로 막아 둠)
- 미국 실시간 무료(0분 지연) 조건을 공식 안내로 확인
- 해외주식 REST 호출 한도
- WEI와 시세 흐름 띠에 쓸 국내·해외 지수를 받을 수 있는지, 실시간인지 지연인지
- 지수 분봉 제공 여부 (지수에서 GIP를 보여줄지 결정)
- HTS ID에 `$`나 `@`가 들어 있을 때의 제한

### 종목 목록(색인) 만들기

- 국내 종목 마스터 파일: 형식과 칸 구성, 시가총액·상장주식수 칸 유무, 영문자가 섞인 종목코드 유무, 실제 종목 수
- 해외 종목 마스터 파일: 한글 이름이 얼마나 채워져 있는지, ADR 여부와 증권 종류 값
- 미국 종목 인기도 목록을 어디서 가져올지, 자산군끼리 인기도를 어떻게 비교할지
- Binance에 있는, 주식 티커 뒤에 B가 붙은 듯한 종목(GOOGLB, BABAB 등)이 무엇인지, 목록에 넣을지

### 환율

- 무료 환율 소스 후보를 실제로 테스트해서 선정
- 분봉 제공 여부 (환율에서 GIP를 보여줄지 결정)

### Binance

- 국내에서 일반 주소 접속이 되는지, 시세 전용 주소가 필요한지

### 블룸버그 관례와 같은지

- KQ = 코스닥, UN·UW·UQ·UA·UP·NAS·NYS·AMS를 US로 읽기
- 통화 코드 하나(KRW, EUR)만 입력했을 때 어떤 환율로 보여주는지
- 줄 첫머리의 기능 코드를 기능으로 읽는지

### 한글 입력 (Windows 11 새·이전 Microsoft IME, macOS 2벌식)

개발 첫 단계에 키 입력 기록 도구를 먼저 만들어서 실제로 확인해요.

- 글자 조합이 끝난 뒤 실제 키 입력 이벤트가 늘 따라오는지, 마지막 입력 이벤트가 그 앞인지 뒤인지
- 조합 중 Tab의 기본 동작을 막아도 글자 마무리가 괜찮은지, 대체 대기 시간 50ms가 적당한지
- 조합 중 마우스 클릭을 했을 때 글자를 강제로 마무리할 수 있는지
- 조합 상태 표시를 한 프레임 늦추는 방식이 Chromium에서 한국어 Enter를 삼키는지
- 한글 모드에서 Ctrl·⌘+글자를 눌렀을 때 어떤 키로 읽히는지
- 알려진 버그의 현재 상태: Chromium 341846848, Electron #32307·#14834
- macOS에서 코드로 띄운 창의 한글 조합 문제 (가설)
- Windows 11 새 IME의 마지막 음절 중복 (블로그 한 곳의 보고뿐)

### 커맨드 라인 입력칸 구현

- (a) 투명한 입력칸 위에 꾸밈을 겹쳐 그리는 방식, (b) 한 줄짜리 CodeMirror 6 중 무엇으로 할지. 한글 입력 시험표로 두 시제품을 비교해서 정해요.

### 단축키

- 사용할 Electron 버전의 기본 메뉴 단축키 목록, Windows에서 메뉴를 없앤 뒤 Alt·F10 동작
- Windows: Ctrl+Shift 언어 전환과 Ctrl+Shift+글자가 겹치는지, Shift+Space 한/영 전환, 일부 IME의 Ctrl+Space 언어 전환
- Mac: Option+글자(악센트 입력), ⌘[·⌘]로 뒤로·앞으로, Ctrl+↓ 시스템 단축키, 명령 팔레트 대상 바꾸기 Option+숫자가 특수 문자 입력과 겹치는지, 메인 창에서 ⌘W(= 앱 종료), 한글 모드의 백틱(₩)

### 여러 창과 성능

- 떼어낸 창이 메인 창과 같은 렌더러 프로세스를 쓰는지 (종목 색인 공유)
- 성능 목표를 실제 종목 마스터로, 차트가 실시간으로 움직이는 중에 측정
  - 키 하나당 자동완성 계산 p95 2ms 이하, p99 4ms 이하
  - 목록 그리기 16ms 이하
  - 새 창의 색인 준비 80ms 이하
  - 색인 다시 만들기 300ms 이하
