## 개발 전에 실제로 확인할 것

### 한국투자증권 API

- 시세만 받을 때 계좌에 예수금이 필요한지
- 실시간 구독의 정확한 최대 개수(예제 코드는 40개로 막아 둠), 체결과 호가가 슬롯을 따로 쓰는지
- REST 호출 한도(실전 초당 약 20건으로 안내됨), 해외주식 REST 한도
- 미국 실시간 무료(0분 지연) 조건을 공식 안내로 확인
- 해외지수·환율(X·KX) 조회의 지연 여부와 분봉 제공 여부. WEI와 시세 흐름 띠에 쓸 국내·해외 지수를 어디까지 받을 수 있는지
- 지수 분봉 제공 여부 (지수에서 GIP를 보여줄지 결정)
- 국내선물옵션: KTB 국채선물이 포함되는지, KOSPI200 야간 시세를 주는지
- 옵션전광판에 내재변동성·그릭스가 들어 있는지
- 장내채권 API가 KRX 일반채권시장만 다루는지
- 해외선물: 무료로 일봉·정산가·미결제약정을 받을 수 있는지, 별도 계좌가 필요한지, CME·SGX 실시간 월 요금
- 종목추정실적·투자의견: 시장 컨센서스인지 KIS 단독 추정인지, 다루는 종목 수와 필드, 이력 길이
- 공매도 잔고 비율 API, 단기과열 지정 종목 목록의 소스
- 해외 권리 정보·해외 순위·해외주식 휴장일 API의 범위
- 재배포 금지 조항 원문
- HTS ID에 `$`나 `@`가 들어 있을 때의 제한. KIS Developers 신청 안내에 나오는 주의 사항이라 신청 전에 확인

### 종목 목록(색인)과 코드

- 국내 종목 마스터 파일: 형식과 칸 구성, 시가총액·상장주식수 칸 유무, 영문자가 섞인 종목코드 유무, 실제 종목 수
- 해외 종목 마스터 파일: 한글 이름이 얼마나 채워져 있는지, ADR 여부와 증권 종류 값
- 미국 종목 인기도 목록을 어디서 가져올지, 자산군끼리 인기도를 어떻게 비교할지
- Binance에 있는, 주식 티커 뒤에 B가 붙은 듯한 종목(GOOGLB, BABAB 등)이 무엇인지, 목록에 넣을지
- K로 시작하는 자체 코드(KINV, KPGM, KCRD, KWRN, KCB, KELS)가 블룸버그 코드와 겹치지 않는지
- 확인하지 못한 블룸버그 니모닉([08](08-bloomberg-coverage.md) §6), DRSK의 실제 설명, 드로잉 도구의 니모닉

### DART·ECOS·KRX·공공데이터

- DART: 하루 호출 한도, 지분공시·임원·타법인출자·채무증권 미상환 잔액 API의 범위
- ECOS: 시장금리 통계표의 항목코드, 호출 한도, 요청당 최대 행 수, KOFR·통안채 시리즈 유무, 한국 지표의 수정치 이력
- KOFR 원천(예탁결제원)에 접근하는 방법
- KOFIA: 최종호가수익률 공표 시점(하루 1회인지 11:30·15:30 두 번인지), 장외 채권 체결 데이터
- 자동 수집이 허용되는지: KOFIA 채권정보센터, KRX 정보데이터시스템, 신용평가사 사이트
- KRX Open API: ETF 일별에 상장좌수·NAV 필드가 있는지(ETF 자금 흐름), 옵션 일별에 내재변동성 필드가 있는지, VKOSPI·금시장 포함 여부, API별 승인 기간
- 공공데이터포털: 금융위원회 채권발행정보 상세, 주식시세정보 데이터셋
- KOSIS 호출 한도, 한국은행·통계청 공표일정의 형식
- ELS 발행 정보 소스(SEIBro 등), Opinet, 조달청 국제원자재가격, 관세청·UN Comtrade, 금융투자협회 펀드 공시

### 해외 데이터

- SEC EDGAR 접근 정책(초당 10건, 연락처 헤더), 13F 데이터셋 주소
- 미국 실적 발표 일정의 무료 소스와 약관. 없으면 SEC 8-K로 발표 뒤에 표시
- 미국 ETF 운용사의 보유 내역 공개 약관 (MEMB 미국 근사)
- FRED 호출 한도, Atlanta Fed 정책금리 확률(MPT)의 접근 방식과 약관, FINRA TRACE 무료 범위, 미국 SDR 공개 데이터
- 각국 정책금리(BIS 등), 영국·독일 금리 커브, 유럽 휴장일 소스, Treasury FiscalData, IMF·OECD·World Bank API 세부
- 한국수출입은행 환율 API의 메뉴와 한도, 네이버 검색 API 하루 한도
- CFTC COT 데이터셋 ID, USDA 농산물 현물, World Bank 월간 원자재 가격
- VKOSPI 소스
- Binance 옵션 API(eapi)가 Deribit을 대신할 수 있는지

### 환율

- 무료 환율 소스 후보를 실제로 테스트해서 선정 (KIS 환율 조회가 1순위 후보)
- 분봉 제공 여부 (환율에서 GIP를 보여줄지 결정)

### Binance

- 국내에서 일반 주소 접속이 되는지, 시세 전용 주소가 필요한지. 규제 동향도 함께 봐요(CRYP 전체에 걸린 위험)

### 블룸버그 관례와 같은지

- KQ = 코스닥, UN·UW·UQ·UA·UP·NAS·NYS·AMS를 US로 읽기
- 통화 코드 하나(KRW, EUR)만 입력했을 때 어떤 환율로 보여주는지
- 줄 첫머리의 기능 코드를 기능으로 읽는지
- 지수선물을 어느 자산군에 두는지, 옵션 티커 형식

### 세금 (PORT 세후 손익 탭)

- 해외주식 양도소득세율(22%)과 기본공제(250만 원), 배당 원천징수, 금융소득 종합과세 기준(2,000만 원)의 최신 값

### 한글 입력

Windows 11 새·이전 Microsoft IME로 확인해요. 개발 첫 단계에 키 입력 기록 도구를 먼저 만들어서 실제로 확인해요. macOS 2벌식은 Mac 기기를 쓸 수 있을 때 확인하고, 그 전에는 확인하지 못한 채로 남아요.

- 글자 조합이 끝난 뒤 실제 키 입력 이벤트가 늘 따라오는지, 마지막 입력 이벤트가 그 앞인지 뒤인지
- 조합 중 Tab의 기본 동작을 막아도 글자 마무리가 괜찮은지, 대체 대기 시간 50ms가 적당한지
- 조합 중 마우스 클릭을 했을 때 글자를 강제로 마무리할 수 있는지
- 조합 상태 표시를 한 프레임 늦추는 방식이 Chromium에서 한국어 Enter를 삼키는지
- 한글 모드에서 Ctrl·⌘+글자를 눌렀을 때 어떤 키로 읽히는지
- 알려진 버그의 현재 상태: Chromium 341846848, Electron #32307·#14834
- macOS에서 코드로 띄운 창의 한글 조합 문제 (가설, Mac 기기가 있을 때)
- Windows 11 새 IME의 마지막 음절 중복 (블로그 한 곳의 보고뿐)

### 커맨드 라인 입력칸과 글꼴

- (a) 투명한 입력칸 위에 꾸밈을 겹쳐 그리는 방식, (b) 한 줄짜리 CodeMirror 6 중 무엇으로 할지. 한글 입력 시험표로 두 시제품을 비교해서 정해요.
- 한글이 정확히 영문 2칸 폭인 고정폭 글꼴(D2Coding 등) 후보를 Windows에서 시험해 선정 (Mac은 기기가 있을 때)

### 단축키

- 사용할 Electron 버전의 기본 메뉴 단축키 목록, Windows에서 메뉴를 없앤 뒤 Alt·F10 동작
- Windows: Ctrl+Shift 언어 전환과 Ctrl+Shift+글자가 겹치는지, Shift+Space 한/영 전환, 일부 IME의 Ctrl+Space 언어 전환
- Mac (Mac 기기를 쓸 수 있을 때): Option+글자(악센트 입력), ⌘[·⌘]로 뒤로·앞으로, Ctrl+↓ 시스템 단축키, 명령 팔레트 대상 바꾸기 Option+숫자가 특수 문자 입력과 겹치는지, 메인 창에서 ⌘W(= 앱 종료), 한글 모드의 백틱(₩)

### 여러 창과 성능

- 떼어낸 창이 메인 창과 같은 렌더러 프로세스를 쓰는지 (종목 색인 공유)
- 성능 목표를 실제 종목 마스터로, 차트가 실시간으로 움직이는 중에 측정 (p95: 100번 중 95번은 이 시간 안에)
  - 키 하나당 자동완성 계산 p95 2ms 이하, p99 4ms 이하
  - 목록 그리기 16ms 이하
  - 새 창의 색인 준비 80ms 이하
  - 색인 다시 만들기 300ms 이하
